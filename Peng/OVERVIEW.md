# PUNG! — 게임 개요

> 밀고 날리는 파티 액션 · WebGL 3D · 외부 라이브러리 0

---

## 한 줄

**총으로 사람을 죽이는 게임이 아니라, 사람을 밀어서 떨어뜨리는 게임.**
체력도 데미지도 없다. 있는 건 넉백 하나뿐이고, 지는 방법도 하나뿐이다 — 판 밖으로 나가는 것.

## 무엇을 하는 게임인가

**펑건(PoofGun)** 은 공기를 터뜨리는 총이다. 맞은 사람은 아프지 않고 **밀려난다**.
이 규칙 하나에서 게임의 모든 것이 나온다.

- 상대에게 쏘면 → 상대가 밀려난다 (**경쟁**)
- 발밑에 쏘면 → 내가 날아간다 (**로켓점프**)
- 팀원 발밑에 쏘면 → 팀원이 날아간다 (**협동**)

같은 동작이 공격이고 이동이다. 그래서 "도망치려면 나를 쏴야 하고, 나를 쏘면 탄이 준다."

## 두 가지 모드

### 경쟁 (Versus) — 마지막까지 판 위에 남기

- 최대 6인 대전. 상대를 떨어뜨리면 1점, **`5 × (인원-1)`점 선취 시 승리**(2인 5 · 6인 25).
- 판은 시간이 지나면 **바깥 고리부터 무너진다.** 도망칠 곳이 점점 줄어든다.
- 떨어져도 죽지 않는다. 곧바로 리스폰되고 점수만 상대에게 간다 — 기다리는 시간이 없다.
- 아이템 패드를 밟으면 능력을 얻는다(맵당 5장).

### 협동 (Co-op) — 둘이 아니면 못 넘는 코스

- 혼자서는 절대 못 넘는 간격이 섞여 있다.
- **리프트 샷**: 팀원을 직격하면 방사형이 아니라 **정확히 위로만** 띄운다.
  (방사형이면 위에서 쏜 사람이 팀원을 바닥에 처박게 되어, 도움이 한 방향뿐이게 된다.)
- 코스마다 "혼자 넘을 수 있는가 / 둘이어야 하는가"를 물리 상수로 계산해 검증한다.

## 기술

### 렌더링
- **WebGL 1 직접 사용.** three.js 같은 것 없음. 셰이더·버퍼·행렬 전부 직접.
- 고전 `<script src>` 로드 — 그래서 `index.html` 을 **더블클릭만 해도 돌아간다**(`file://`).
- 카툰 룩: 정점 색 + 인버티드 헐 윤곽선(플레이어·총·아이템·맵 조각 전부).
- 중력 렌즈: 폭발 순간 화면이 실제로 휜다(FBO 후처리).

### 물리
| 값 | |
|---|---|
| 달리기 | 5.3 m/s |
| 점프 정점 | 1.68 m |
| 폭발 반경 / 위력 | 4.2 m / 13.5 |
| 탄창 | 3발, 1.1초마다 1발 |
| 시뮬 주기 | 120 Hz 고정 |

조작감을 위한 유예 장치들 — **코요테 타임**(발판을 벗어난 뒤 0.09초), **점프 선입력**(0.12초),
**폭발 점프 유예**(발밑을 먼저 쏘고 점프해도 받아준다).

### 충돌 — 상자가 아니라 실제 폴리곤
에셋 모양대로 부딪힌다. 메시 삼각형을 그대로 월드 삼각형 수프로 만들고,
균일 격자(1.5m)로 broadphase, 분리축(SAT) 13개로 판정한다.

- 걸을 수 있는 최대 경사를 **법선**으로 판정 — 높이차로만 보면 어떤 벽이든 조금씩 기어오른다.
- 이동을 12cm 단위로 쪼개 터널링을 막는다.
- **P 키**로 콜리전을 눈으로 확인할 수 있다.
- 그려지는 삼각형과 판정 삼각형이 같은지 자동 검사한다(양방향).

### 멀티플레이 — 의존성 0 릴레이 서버
- `node server.js` 한 줄. `npm install` 없음. WebSocket 핸드셰이크·프레이밍까지 직접 구현.
- 6자리 세션 코드로 방 참가.
- 각 클라이언트가 자기 물리를 돌리고 상태(22Hz)와 폭발만 보낸다. 서버는 중계만.
- **넉백은 쏜 쪽이 계산해 보낸다.** 예전에는 맞는 쪽이 다시 판정했는데, 지연이 0.5~0.7초
  쌓여서 실제 서버에서는 펑건이 거의 안 먹었다. 쏜 쪽이 빗나갔다고 보면 빗나간 것이다 —
  반경·세기는 몸에 직접 먹이는 쪽과 실어 보내는 쪽이 **같은 함수**로 낸다.
- **점수는 서버가 되돌려 준 한 줄로만 센다.** 로컬에서도 세면 그 화면에서만 2배가 된다.
- AI 참가자를 방에 추가할 수 있다(방장이 대신 굴린다).
  방장이 특별한 것은 방 설정(맵·모드·시작)뿐이고, 점수·승패에는 권위가 없다.

### 맵 에디터 (`kiteditor.html`)
게임과 같은 코드로 도는 인게임 에디터.
- Kenney 킷 **5벌 487조각**(서바이벌·정거장·공장·숲·프로토타입) 탭으로 전환
- 드래그해서 배치, 언리얼식 기즈모(W 이동 / E 회전 / R 크기), 우클릭 드래그 시점
- 리스폰·아이템 패드 배치, 더미 플레이어로 크기 확인
- 저장하면 `levels/` 에 바로 파일이 써진다(로컬에서만)

### 에셋
Kenney CC0 킷을 GLB에서 굽고, 텍스처를 **정점 색으로 구워** 넣는다.
그래서 런타임에 텍스처 파일이 하나도 없고, 로딩도 없다.

## 이 프로젝트에서 배운 것

**"눈으로 확인했다"는 검증이 아니다.**
이 게임의 버그 대부분은 눈으로는 멀쩡해 보였다.

- 콜리전이 메시와 어긋나 보인 것 → 실제로는 **충돌이 아예 없는 조각**이었다.
  한 방향으로만 검사하다 놓쳤고, 반대 방향(“이 충돌에 대응하는 메시가 있나”)을 돌리자
  25,848개가 바로 나왔다.
- 맵 소품이 서로 박힌 것 → 각도를 손으로 적어서였다. 고리 위 균등 배치 + 겹침 검사로 바꿨다.
- 조각이 이음매에 걸터앉은 것 → 격자 킷에 극좌표로 놓아서 반 칸씩 밀린 것이었다.
- 멀티에서 펑건이 안 먹은 것 → 로컬에서는 지연 사슬이 없어 재현되지 않았다.

그래서 지금은 고칠 때마다 **숫자로 재고 기록한다** — 스폰 착지율, 바닥 구멍 수,
넉백 낙사 비율, 겹친 쌍 수, 물리 비용(µs), 화면 픽셀 비율까지.
