# PENG! — 밀고 날리는 파티 액션

WebGL 3D FPS(외부 라이브러리 없음). PoofGun(공기폭발 총)으로 발밑을 쏴 **로켓점프**로 협곡을 넘어 결승선까지. 솔로 또는 여러 명 협동.

## 혼자 플레이 (오프라인)

`index.html`을 브라우저로 그냥 열면 됩니다. 외부 라이브러리·인터넷 불필요. 멀티는 자동으로 비활성(솔로)로 폴백됩니다.

## 멀티플레이 (세션 코드로 함께)

의존성 0 Node 서버가 포함되어 있습니다. `npm install` 필요 없음.

```bash
node server.js
```

접속: <http://localhost:8090/>

> ⚠️ **반드시 위 주소로 여세요.** `index.html` 파일을 더블클릭해서 열거나(`file://`),
> 다른 정적 서버(예: `python -m http.server`) 주소로 열면 그쪽에는 멀티 서버가 없어
> "멀티 서버에 연결할 수 없습니다"가 뜹니다. 메인 메뉴 하단에 현재 상태
> (🟢 준비됨 / ⚠️ 안내)가 표시되니 확인하고 시작하세요.

### 함께 하는 순서

1. **호스트**: 메인 메뉴에서 **방 만들기** → 6자리 **세션 코드**가 나오고 대기방으로 이동
2. 그 코드를 친구에게 알려줍니다 (대기방의 *코드 복사* 사용)
3. **친구**: 같은 주소로 접속 → **방 참가하기** → 코드 입력 → 대기방 합류
4. 대기방에 2명 이상이 되면 호스트의 **게임 시작** 버튼이 활성화 → 누르면 **전원 동시 시작**

- 포트 변경: `PORT=3000 node server.js`
- 친구가 **다른 PC**에서 들어오려면 같은 공유기라면 호스트 PC의 내부 IP로 접속(`http://192.168.x.x:8090/`),
  인터넷 너머라면 8090 포트 개방 또는 터널(ngrok 등)이 필요합니다.
- 없는 코드를 입력하면 "방을 찾을 수 없어요"로 거부됩니다(빈 방이 생기지 않음).

### 동작 방식 (릴레이 넷코드)

각 클라이언트가 자기 물리를 로컬에서 돌리고, 자기 상태(위치·시점·반동)와 발사한 **폭발(blast)** 만 서버로 보냅니다. 서버는 같은 방의 다른 사람에게 그대로 중계합니다.

- 상대는 **청록 캡슐 + 총**으로 렌더됩니다.
- **핵심 협동**: 팀원이 쏜 펑건 폭발 반경 안에 있으면 **날아갑니다** — 서로 밀어서 협곡을 넘겨주세요!

## 협동 기믹

폭발 넉백은 **방사형**이다(폭발 중심 → 몸). 그래서 원래는 팀원의 **발밑을 받쳐 쏘는** 한 방향만
도움이 됐고, 위에서 아래로 쏘면 팀원이 오히려 처박혔다. 그 결과 협동 전용 구간은 **편도**였다 —
한 명은 넘어가고 남은 한 명은 영영 못 넘는다. 협동 승리는 개인별이라 정말로 한 명만 골인했다.

### 리프트 샷 — 팀원 직격

팀원을 **근접 신관(`FUSE_R` 1.3m) 안으로 직격**하면 방사형 대신 **정확히 위로만** 밀어준다
(`PHYS.LIFT_V`, 기본 9.0m/s · 거리 감쇠 없음). 위에 먼저 올라간 사람이 아래를 향해 쏴서
남은 팀원을 끌어올릴 수 있다 — 이제 도움이 **양방향**이다.

- 직격 폭발은 색이 다르다(연청록). 쏜 쪽이 제대로 맞혔는지 바로 안다.
- **경쟁 모드에서는 꺼진다.** 밖으로 밀어내는 게 목적인데 수직으로만 띄우면 넉백이 죽는다.
- 거리 감쇠를 두지 않은 이유: "팀원이 얼마나 가까이서 쐈나"에 따라 도달거리가 흔들리면
  에디터의 도달 분석을 믿을 수 없게 된다. 고정값이라 설계 숫자가 그대로 맞는다.

### 연동 압력판

`plate:'a'` 를 누군가 **밟고 있는 동안에만** 같은 채널의 `link:'a'` 발판이 실체가 된다
(충돌·광선·발판 전부). 밟는 사람은 건널 수 없으므로, 건너간 사람이 **반대편 판을 밟아
되갚아 주는 왕복 릴레이**가 된다.

상대 위치는 이미 매 프레임 중계되므로 **새 프로토콜이 필요 없다** — 양쪽이 각자 같은 판정을 한다.
꺼진 다리는 지우지 않고 어둡게 남긴다(생길 자리가 보여야 퍼즐이 성립한다).

### 관문 체크포인트

체크포인트에 `gate:true` 를 달면 **거기까지만 되돌린다.** 떨어지면 한 덩어리를 다시 올라가야 한다.
체크포인트 자체는 발판마다 촘촘히 둘 수 있다 — 에디터의 경로 분석이 체크포인트 순서를
따라가므로 촘촘해야 정확하기 때문이다. `gate` 가 없는 맵은 예전대로 마지막 체크포인트로 돌아간다.

### AI 참가자 (혼자서도 경쟁 플레이)

대기방에서 방장이 **+ AI 추가** 를 누르면 AI 참가자가 들어온다(최대 6). 사람이 없어도
2명이 되므로 혼자서 경쟁 모드를 돌릴 수 있다. 게스트 화면에서는 사람과 구별되지 않는다.
몸통 색은 **무작위**로 뽑는다(HSL 에서 채도·명도를 묶어 어두운 배경에 묻히지 않게).

> **AI 는 방장의 클라이언트가 돌린다.** 서버는 순수 중계라 물리도 레벨도 없어서
> 봇을 돌릴 수 없다. 서버가 하는 일은 '가상 참가자 슬롯'을 잡아 주고, 방장이 그
> 슬롯 이름으로 보내는 `st`·`bl`·`fell` 을 중계하는 것뿐이다.
> `st`/`bl` 은 원래 보낸 사람 id 로 덮어써서 사칭을 막는데, 봇은 **그 봇을 소유한
> 연결일 때만** 예외로 봇 id 를 허용한다.

봇도 사람과 **똑같이 `stepSim` 을 돌린다** — 별도 물리를 만들면 반드시 어긋난다.
봇 상태를 매 프레임 `MP.peers` 에 넣어 두므로 렌더·플레이어 충돌·근접 신관이 전부 그대로 동작한다.

행동 우선순위(위가 우선):

1. **낙하 복귀** — 떨어지는 중이면 발밑을 쏴 다시 뜨고, 동시에 판 가운데로 민다
2. **붕괴 회피** — 지금 서 있는 고리가 다음에 무너질 고리면 상대고 뭐고 안쪽으로 물러난다
3. **낭떠러지 회피** — **가려는 방향**을 짚어 바닥이 없으면 가운데로 튼다
4. **교전** — 6.5m 밖이면 접근, 3m 안이면 후퇴, 그 사이는 상대 주위를 돈다.
   상대 **발밑**을 노려 쏜다(넉백이 위로 떠야 밀린다). 조준 오차 0.1rad · 발사 간격 0.55초

표적은 **가장 가까운 상대**다 — 사람이든 다른 AI 든 가리지 않는다. 자기 자신은
`MP.peers` 에도 들어 있으므로(렌더·충돌 재사용) 반드시 뺀다.

추가로 **끼임 탈출**(가려는데 안 움직이면 점프 → 그래도 안 되면 방향 전환)과
**코앞 사격 금지**(2.4m 안에 뭔가 막고 있으면 참는다)가 있다.

> 3번은 정면이 아니라 **이동 방향**을 짚어야 한다. 정면만 보면 옆걸음 중에 낭떠러지를
> 그대로 밟는다. 2번이 없으면 표적만 보고 버티다 발밑이 통째로 사라진다.
>
> 봇은 점프를 자발적으로 하지 않으므로 계단·벽·탑 앞에서 영영 비벼댄다 — 끼임 탈출이 필요하다.
>
> 코앞 사격 금지의 기준은 **폭발 반경(4.2m)이 아니라 2.4m** 다. 봇은 상대 *발밑* 을 노리므로
> 광선이 표적 근처 바닥에 닿는 게 정상인데, 기준을 폭발 반경으로 잡으면 정상 사격까지
> 전부 막혀 사격 수가 3분의 1로 줄었다(56 → 17).

> **봇이 쏜 건 방장 화면에서 안 보였다.** 연출(탄·폭발·파편)을 내 `sim` 것만 그렸는데
> 봇의 탄은 `bot.sim` 에 들어가기 때문이다. 게스트는 `bl` 을 받아 자기 `sim` 에 만들어서
> 멀쩡히 보였다 — 방장만 안 보이는 종류의 버그다. 지금은 봇 `sim` 들의 연출도 함께 그린다.
> 두 규칙을 넣기 전후 실측(30초, 방장은 가만히 서 있음):
>
> | | 봇 자멸 | 방장을 밀어낸 횟수 |
> |---|---|---|
> | 이전 | 1 · 4회 | 2회 |
> | 이후 | 0 · 2회 | 12회 |

### 아이템 패드

아레나 바닥의 **원판 패드**를 밟으면 아이템이 하나 나온다(20초 쿨다운 후 재생성).
원판 지름은 캐릭터 지름(0.7m)과 같고, 몸이 원판에 닿으면 집힌다.
패드는 스폰(반경 6)과 가운데 단(반경 2.2) 사이에 있어서, 집으러 가려면 반드시 자기 자리를
비우고 가운데로 나와야 한다. 고리 2 라서 중반에 무너지고, 후반에는 가운데 단 위 하나만 남는다.

**원판은 어느 패드든 똑같은 색이다.** 무작위인 건 그 위에 떠 있는 **내용물 표식**뿐이다.
아이템마다 모양·색이 달라서 보고 판단해 가져갈지 정하게 된다(자리 싸움이 생긴다).
표식은 **3D 메시**다(Kenney Food Kit, [3D 메시 넣기](#3d-메시-넣기-glb) 참고).
HUD 아이콘과 **같은 그림에서 나온 것**이라, 패드에서 본 물건을 HUD 에서 바로 알아본다.
구운 데이터가 없으면 원래의 작은 큐브 조합으로 떨어진다 — 회전 메시가 없던 시절
큐브가 작아야 'Y축으로 도는 궤도'가 어색하지 않고 의도한 것처럼 보였기 때문이다.

> 큐브 시절에는 드럼·닻·펄스를 안 돌렸다(`spin:false`). 축 정렬 큐브가 도는 게
> 어색해서였는데, **실물 메시에는 그 이유가 없다.** 6종 중 3종이라 판에 정지한 표식이
> 절반을 넘었고(9패드 중 7개가 멈춰 있던 판도 나왔다), 안 돌면 뒤에서 다가갈 때
> 뒷면만 보인다. 그래서 `spin` 은 이제 **큐브 표식에만** 걸린다.

패드는 **세 겹**으로 그린다.

| 겹 | 색 | 역할 |
|---|---|---|
| 기본 바탕 원판 | `#16222f` | 패드 자리 |
| 빈 링 트랙 (항상 한 바퀴) | `#44607d` | 게이지가 찰 자리 |
| 차오른 링 | `#3fe0b4` | 진행도 |

**준비 상태 = 링이 100% 찬 모습**이다. 집어가면 표식이 사라지고 링이 0 부터 다시 찬다.
다 차면 다음 아이템이 나타난다 — 숫자 없이도 "지금 집을 수 있나 · 언제 다시 오면 되나"가
멀리서 읽힌다. 바탕과 빈 트랙은 색이 확실히 달라야 한다(같으면 빈 구간이 바탕에 묻힌다).
세 겹이 같은 높이면 z-파이팅이 나므로 조금씩 띄워 얹는다.

패드 자리도 **라운드마다 바뀐다**. 4겹 대칭 궤도를 **두 개** 골라 4+4, 거기에 가운데
하나를 더해 **항상 9개**다(서버가 패드 번호로 쿨다운을 재므로 개수는 고정이어야 한다).

> 궤도를 하나만 고르면 나올 수 있는 배치가 궤도 수(약 17개)로 묶여 "매번 같은 자리"처럼
> 보인다. 두 개면 조합이 90가지를 넘는다. 되도록 서로 다른 고리에서 뽑아 한쪽에 몰리지
> 않게 한다. 가운데 패드는 남긴다 — 판이 3×3 까지 줄어들면 바깥 패드는 전부 무너져
> 막판에 아이템이 아예 없어진다.

**대기방 연습장에서는 패드를 그리지 않는다.** `padTick` 이 `practice` 를 건너뛰어
어차피 못 먹는데, 떠 있으면 먹을 수 있는 줄 알고 밟으러 가게 된다.

> 스폰 지점은 패드에서 판정 반경 밖으로 떨어뜨려야 한다. 아레나 `start` 가 패드에서
> 0.4m 라 솔로로 들어가면 서자마자 아이템이 주워졌다.

### 아이템 HUD

탄창 위(우하단)에 현재 상태가 뜬다. 두 종류를 구분한다.

- **작동 중**(실선 테두리) — 시간이 흐르는 버프. 아이템 색, 남은 초, 아래에 진행 바.
- **보유 중**(점선 테두리) — 내가 눌러야 나가는 것. 어떤 키인지 같이 뜬다(펄스 `F`, 글라이딩 `Space`).

줄 구성이 바뀔 때만 DOM 을 다시 만들고 평소엔 숫자와 바 길이만 갱신한다 —
매 프레임 `innerHTML` 을 다시 쓰면 레이아웃이 계속 다시 계산된다.

| 아이템 | 효과 | 지속 |
|---|---|---|
| 🌀 **리버스캡슐** | 폭발이 밀어내는 대신 **끌어당긴다**. 상대를 내 쪽 낭떠러지로 당기거나 발판에 매달릴 때. 로켓점프는 못 한다 | 12초 |
| 💥 **과충전** | 폭발 위력 ×1.8 · 반경 ×1.25. 실측 넉백 2.85배 | 12초 |
| 🥁 **드럼 탄창** | 탄창 즉시 충전 + 재장전 3배. 계속 밀어붙이는 용 | 15초 |
| 🪶 **깃털** | 받는 반동 ×1.7 · 중력 ×0.6. **더 멀리 날지만 더 잘 날아간다**. 공중에서 `Space` 한 번 더 → **1초 글라이딩**(1회) | 15초 |
| ⚓ **닻** | 받는 반동 ×0.35. 안 밀린다 — 대신 로켓점프도 약해져 기동을 잃는다 | 10초 |
| ⚡ **펄스** | `F` — 내 주위로 대형 폭발(위력 ×2 · 반경 ×1.6). 붙은 상대를 떼어낸다. 나에게는 안 걸린다 | 1회 |

깃털과 닻이 정반대인 게 핵심이다 — 뭘 주웠느냐에 따라 같은 상황에서 정반대로 움직여야 한다.

효과는 두 갈래로 나뉜다.

- **탄에 실리는 것**(리버스·과충전·펄스) — 내 총이 만드는 폭발의 성질이다. 쏘는 순간
  탄에 도장을 찍고 `bl` 메시지에 실어 보낸다. 상대 화면에서도 같은 성질로 터져야 한다.
  날아가는 도중에 아이템이 끝나도 이미 나간 탄은 원래대로 터진다.
- **몸에 걸리는 것**(깃털·닻·드럼) — 각자 자기 물리를 돌리므로 로컬에만 적용하면 되고
  동기화가 필요 없다.

깃털 글라이딩은 깃털을 주울 때마다 1회 충전된다. 깃털은 원래 "잘 날지만 잘 날아간다"는
양날인데, 날아간 뒤 손쓸 방법이 없어 순수 손해로 느껴질 때가 있었다 — 이 1초가 복귀 수단이다.
글라이딩 중에는 최대 낙하속도가 1.4m/s 로 묶인다(실측: 같은 1초에 일반 낙하 22.2m → 1.4m).

> **패드 내용물과 중재는 서버가 쥔다.** 내용물이 표식으로 미리 보이므로 전원이 같은 걸
> 봐야 하고, 그래서 서버가 정해 `padset` 으로 뿌린다. 밟으면 서버가 "누가 먼저인가"를
> 판정해 저장해 둔 그 아이템을 주고(`pad`), 곧바로 다음 내용물을 굴려 다시 알린다.
> 방에 늦게 들어온 사람도 `join` 시점에 현재 내용물을 전부 받는다.
> `server.js` 의 `ITEM_POOL` 은 `index.html` 의 `ITEMS` 키 목록과 맞춰야 한다.

아이템은 **라운드를 넘기지 못한다**(들고 시작하면 불공평하다). 패드 쿨다운은 서버가
방 단위로 재므로 라운드와 무관하게 흐르고, 새 경기(`start`)에서만 초기화된다.

### 무너지는 바닥 (경쟁 전용)

경기는 **멈추지 않는다.** 누가 떨어지면 점수만 오르고 그 자리에서 바로 부활하며,
먼저 **5점**을 낸 사람이 이긴다. 정산도 라운드 정지도 없다.

**점수는 민 사람에게만 간다.** 최근 6초 안에 맞은 폭발의 주인이 점수를 얻고,
스스로 떨어지면 아무도 못 얻는다(채팅에 `— AI 3` / `(자멸)` 로 표시).

> 예전엔 '떨어진 사람 빼고 전원 +1' 이었다. 1대1 에서는 같은 결과라 문제가 없었는데,
> AI 끼리도 싸우게 되자 **구석에서 구경만 해도 점수가 쌓여 이겼다** —
> 방장을 200m 밖에 세워 두고 20초를 돌리니 5:4 로 승리했다. 지금은 0점이다.

> **리스폰은 발밑이 남아 있는 스폰만 고른다.** 바깥 고리가 무너진 뒤에도 원래 자리로
> 보내면 허공에 떨어져 무한히 실점한다. 전부 사라졌으면 가운데(항상 남는 고리)로 보낸다.

판이 바닥까지 무너지고 5초가 지나면 **새 판이 통째로 깔린다**(`newArena`).
그때도 조작은 멈추지 않는다 — 다만 옛 발판이 사라지므로 위치만 스폰으로 옮겨 준다.

**아레나 바닥은 레벨 파일에 없다.** `collapse` 스펙만 있고 게임이 만들어 깔아준다.
지름 **28.6m**(타일 2.6m, 고리 0~5). 각 타일은 중심에서 몇 번째 고리인지를 들고
있고, 15초 뒤부터 3.6초마다 **바깥 고리부터** 무너진다. 무너지기 1.4초 전에 해당 고리가
주황색으로 깜빡여 예고한다. 가운데 3×3(고리 0·1)은 남겨서 최후의 결전장이 된다.
바닥 위 구조물도 자기 고리와 함께 떨어진다 — 안 그러면 허공에 뜬다.

### 절차적 생성 — 우주 정거장 (`PENG.genStation`)

판은 **Kenney Space Station Kit**(CC0) 조각으로 조립한다. 예전엔 원판을 깔고 구멍을
파는 방식이었는데, 아무리 손봐도 '구멍 뚫린 지형 덩어리'였지 건축물이 아니었다.
이제 실제 정거장처럼 **코어에서 복도를 뻗고 끝에 포드를 붙인다**.

```
        #P#            S = 스폰(포드 중심)
        #S#|           P = 아이템 패드
       |###|           # = 바닥
        |#|            | = 벽
    ||   P|  |
   ###||### |###
   PS##P#P#P##SP       ← 허브(중앙 3x3) + 복도 4갈래 + 포드 4개
   ###| ###||###
     |  |P   ||
        |#|
       |###|
       |#S#
        #P#
```

| 모듈 | 내용 | 분리 순서 |
|---|---|---|
| **코어** 3×3 | 중앙 허브. 소품 약간, 벽 적음 | 0 (안 떨어짐) |
| **복도** 1칸 폭 × 2~4 | 난간만 있는 통로 — 최고의 넉백 지점 | 1부터 바깥으로 |
| **포드** 3×3 또는 5×5 | 벽·창·문 + 엄폐물. 스폰 자리 | 복도 다음 |
| **위성** | 협곡 너머 발판(로켓점프 표적) | 가장 먼저 |

붕괴가 아니라 **모듈 분리**다. 바깥 모듈부터 통째로 떨어져 나가고 코어만 남는다.
내부적으로는 각 충돌체에 `_ring = 분리 순서`를 넣어 기존 붕괴 코드를 그대로 쓴다.

> **벽은 '칸' 단위로 놓는다.** 킷의 `wall` 은 슬래브가 칸 **중심선**에 있다(모서리가 아니라).
> 처음엔 칸 모서리에 놓았는데, 그러면 직각으로 만나는 두 벽이 0.3×0.3 만큼 **서로를 뚫고
> 지나간다.** 그래서 포드는 바닥 위에 **벽 칸 고리**를 둘러 방을 만들고,
> 꺾이는 칸에는 킷이 그러라고 준 **`wall-corner`** 를 쓴다.
>
> `wall-corner` 의 팔은 rot 0 에서 +X·+Z 를 향한다(형상 실측) → rot 1 = +X·−Z,
> rot 2 = −X·−Z, rot 3 = −X·+Z. 팔이 들어오는 칸은 `wall-door` 라 걸어서 드나든다.
>
> **`wall-corner` 는 원점이 어긋나 있다.** `wall` 의 슬래브는 칸 중심선(z=0)에 있는데
> 코너의 두 팔은 ±0.25 에 있어서 그냥 놓으면 벽과 0.25 만큼 벌어진다. 두께는 둘 다
> 0.3 으로 같으므로 로컬에서 **(−0.25, −0.25)** 옮기면 팔이 이웃 벽 슬래브와 정확히
> 한 줄이 된다. 보정은 `PIECE_OFF` 에 둔다.
>
> 그런데 정렬만 하면 **깜박인다.** 코너의 팔은 0.8 인데 필요한 길이는 0.65 라 이웃 벽과
> 0.44m 겹치고, 그 구간에서 **옆면이 정확히 같은 평면**이 되어 z-파이팅이 난다
> (실측: 겹친 박스쌍 28개 전부 동일 평면).
> 길이를 줄이면 이번엔 틈이 벌어진다. 그래서 겹침은 그대로 두고 조각만 **3% 줄여**
> 옆면이 벽면보다 4.5mm 안쪽에 오게 한다(`PIECE_SCALE`) — 같은 평면이 사라져 깜박임이
>없어지고, 겹침이 남아 있어 틈도 안 생긴다(실측: 동일 평면 28 → 0, 접합 28/28 틈 없음).
>
> 궤도 대표는 네 회전본 중 아무거나라, 벽 방향은 **'+Z 쪽 포드에 속한 복사본'을 기준**으로
> 계산하고 나머지는 회전만 얹는다. 그러지 않으면 문이 팔 반대쪽에 뚫린다.
>
> **정중앙(0,0)은 90° 돌려도 제자리**라 궤도가 4중으로 접힌다. 그대로 돌리면 같은 자리에
> 조각이 네 장 쌓이므로 중복을 걸러야 한다.
>
> 복도·코어·위성은 벽 없이 열어 둔다 — 실측: 난간(1.18m)만 둘러도 **폭발로 6/6 전부
> 못 넘어간다.** 넉백이 수평이라 낮은 턱에 그대로 걸린다. 떨어질 자리가 없으면 경기가 죽는다.
>
> 같은 이유로 **포드 고리도 빈틈없이 두르면 안 된다.** 닫힌 상자가 되면 밀려도 벽에
> 막혀 아무도 밖으로 안 날아간다(실측: 낙하 5/12 → **0/8**, 평균 이동 8.5m → 1.6m).
> 직선 구간의 40% 는 비워 둔다 — 모서리 기둥과 문은 남긴다.

> 결정은 **회전 궤도당 한 번**만 내리고 네 칸에 똑같이 적용한다(방향 `d` 도 함께 돈다).
> 칸마다 굴리면 같은 자리인데 한쪽만 벽이고 다른 쪽은 난간이 되어 대칭이 깨진다.

### 충돌은 조각 모양에서 뽑는다

손으로 "벽 = 1×1×0.3" 식으로 적으면 **문이 뚫린 벽도 통짜**가 되고 탁자 밑도 막힌다.
대신 조각의 XZ 를 8×8 격자로 나눠 기둥마다 *지오메트리가 있는 y 구간*을 재고,
같은 구간을 가진 기둥을 직사각형으로 합친다. 킷 조각은 대부분 상자를 이어 붙인
형태라 이 방법이 모양을 거의 그대로 잡는다.

| 조각 | 충돌 박스 | 결과 |
|---|---|---|
| `floor` / `-detail` / `-panel` | 1 | 평평한 데크(장식 요철 무시) |
| `wall` / `wall-window` | 1 | 막힘 |
| **`wall-door`** | **3** | 기둥 둘 + 상인방 → **지나갈 수 있다** |
| `container` / `skip` / `table` | 3~13 | 모양대로 |
| `rail` | 1 (통짜) | 낮은 벽 — 기둥 방식으로 뽑으면 사이가 숭숭 빈다 |

> 기둥 안에 지오메트리가 있는지는 "기둥 중심이 삼각형의 XZ 투영 안에 있는가"로 본다.
> 삼각형의 XZ 바운딩박스를 쓰면 넉넉하게 잡혀 **문 구멍이 도로 막힌다.**
>
> 병합 키만 0.05유닛으로 뭉개고 **박스 크기는 원래 값을 쓴다.** 예전엔 `hi` 를 올림해서
> 조각이 통째로 부풀었고, 그 바람에 데크 윗면이 0 대신 +0.15m 가 돼 문 상인방에
> 머리가 3cm 걸렸다.
>
> **바닥만은 예외로 평평한 한 장**으로 친다. 표면 요철까지 판정에 넣으면 데크에
> 15~30cm 턱이 흩어져 달리다 걸린다 — 빠르게 밀고 밀리는 경기에서 그건 그냥 사고다.
>
> **1유닛 = 2.95m 인 이유**: 킷의 문 구멍이 0.65유닛인데 플레이어가 1.8m 라,
> 2.6 으로 두면 구멍이 1.69m 라서 문을 못 지나간다(Kenney 는 더 작은 캐릭터 기준).
> 2.95 면 1.92m 가 되어 머리 위로 여유가 생긴다.

> **충돌 박스는 그리지 않는다(`_hide`).** 정거장은 킷 조각을 따로 그리므로, 충돌체까지
> 그리면 같은 자리에 상자가 한 겹 더 얹혀 조각을 뚫고 나온다. 실측 125개 중 124개가
> 충돌 전용이고, 그려지는 박스는 저 아래 배경 바닥 하나뿐이다.
>
> 다만 "곧 분리된다"는 예고가 그 박스 색으로 표시되므로, 깜빡이는 동안만 윗면에
> **얇은 경고판**을 깔아 준다 — 안 그러면 예고가 통째로 사라진다.

**렌더는 정적 VBO 하나다.** 조각이 100~300개라 매 프레임 CPU 로 옮기면 낭비인데,
분리될 때 말고는 안 움직인다. 판을 만들 때 한 번 정점을 굽고 드로우콜 하나로 그린다.
분리가 일어난 그때만 다시 만든다(경기당 서너 번). 킷 색만 쓰면 면 구분이 안 돼서
구운 법선으로 간이 방향광을 넣는다.

> 킷은 **1×1 격자 · 원점 중심 · Y=0 바닥**으로 완전히 일관된다(98개 전부 실측 확인).
> 1유닛 = **2.6m** 로 잡으면 벽이 2.6m(플레이어 1.8m)가 되고 기존 물리 상수가 그대로 맞는다.
> 바닥 조각은 `y=-0.3` 에 놓아 데크 윗면이 y=0 이 되게 한다.
>
> **다중 노드 조각은 안 쓴다.** `structure` 같은 건 노드가 13개인데 로더가 단일 노드만
> 읽는다. 쓰는 14종은 전부 단일 노드임을 확인했다.

### 아이템 패드### 아이템 패드

아레나 바닥의 **원판 패드**를 밟으면 아이템이 하나 나온다(20초 쿨다운 후 재생성).
원판 지름은 캐릭터 지름(0.7m)과 같고, 몸이 원판에 닿으면 집힌다.
패드는 스폰(반경 6)과 가운데 단(반경 2.2) 사이에 있어서, 집으러 가려면 반드시 자기 자리를
비우고 가운데로 나와야 한다. 고리 2 라서 중반에 무너지고, 후반에는 가운데 단 위 하나만 남는다.

**원판은 어느 패드든 똑같은 색이다.** 무작위인 건 그 위에 떠 있는 **내용물 표식**뿐이다.
아이템마다 모양·색이 달라서 보고 판단해 가져갈지 정하게 된다(자리 싸움이 생긴다).
표식은 작은 큐브 몇 개로 만든다: 회전 메시가 없어서 큐브가 작아야 'Y축으로 도는 궤도'가
어색하지 않고 의도한 것처럼 보인다.

패드는 **세 겹**으로 그린다.

| 겹 | 색 | 역할 |
|---|---|---|
| 기본 바탕 원판 | `#16222f` | 패드 자리 |
| 빈 링 트랙 (항상 한 바퀴) | `#44607d` | 게이지가 찰 자리 |
| 차오른 링 | `#3fe0b4` | 진행도 |

**준비 상태 = 링이 100% 찬 모습**이다. 집어가면 표식이 사라지고 링이 0 부터 다시 찬다.
다 차면 다음 아이템이 나타난다 — 숫자 없이도 "지금 집을 수 있나 · 언제 다시 오면 되나"가
멀리서 읽힌다. 바탕과 빈 트랙은 색이 확실히 달라야 한다(같으면 빈 구간이 바탕에 묻힌다).
세 겹이 같은 높이면 z-파이팅이 나므로 조금씩 띄워 얹는다.

패드 자리도 **라운드마다 바뀐다**. 4겹 대칭 궤도를 **두 개** 골라 4+4, 거기에 가운데
하나를 더해 **항상 9개**다(서버가 패드 번호로 쿨다운을 재므로 개수는 고정이어야 한다).

> 궤도를 하나만 고르면 나올 수 있는 배치가 궤도 수(약 17개)로 묶여 "매번 같은 자리"처럼
> 보인다. 두 개면 조합이 90가지를 넘는다. 되도록 서로 다른 고리에서 뽑아 한쪽에 몰리지
> 않게 한다. 가운데 패드는 남긴다 — 판이 3×3 까지 줄어들면 바깥 패드는 전부 무너져
> 막판에 아이템이 아예 없어진다.

**대기방 연습장에서는 패드를 그리지 않는다.** `padTick` 이 `practice` 를 건너뛰어
어차피 못 먹는데, 떠 있으면 먹을 수 있는 줄 알고 밟으러 가게 된다.

> 스폰 지점은 패드에서 판정 반경 밖으로 떨어뜨려야 한다. 아레나 `start` 가 패드에서
> 0.4m 라 솔로로 들어가면 서자마자 아이템이 주워졌다.

### 아이템 HUD

탄창 위(우하단)에 현재 상태가 뜬다. 두 종류를 구분한다.

- **작동 중**(실선 테두리) — 시간이 흐르는 버프. 아이템 색, 남은 초, 아래에 진행 바.
- **보유 중**(점선 테두리) — 내가 눌러야 나가는 것. 어떤 키인지 같이 뜬다(펄스 `F`, 글라이딩 `Space`).

줄 구성이 바뀔 때만 DOM 을 다시 만들고 평소엔 숫자와 바 길이만 갱신한다 —
매 프레임 `innerHTML` 을 다시 쓰면 레이아웃이 계속 다시 계산된다.

| 아이템 | 효과 | 지속 |
|---|---|---|
| 🌀 **리버스캡슐** | 폭발이 밀어내는 대신 **끌어당긴다**. 상대를 내 쪽 낭떠러지로 당기거나 발판에 매달릴 때. 로켓점프는 못 한다 | 12초 |
| 💥 **과충전** | 폭발 위력 ×1.8 · 반경 ×1.25. 실측 넉백 2.85배 | 12초 |
| 🥁 **드럼 탄창** | 탄창 즉시 충전 + 재장전 3배. 계속 밀어붙이는 용 | 15초 |
| 🪶 **깃털** | 받는 반동 ×1.7 · 중력 ×0.6. **더 멀리 날지만 더 잘 날아간다**. 공중에서 `Space` 한 번 더 → **1초 글라이딩**(1회) | 15초 |
| ⚓ **닻** | 받는 반동 ×0.35. 안 밀린다 — 대신 로켓점프도 약해져 기동을 잃는다 | 10초 |
| ⚡ **펄스** | `F` — 내 주위로 대형 폭발(위력 ×2 · 반경 ×1.6). 붙은 상대를 떼어낸다. 나에게는 안 걸린다 | 1회 |

깃털과 닻이 정반대인 게 핵심이다 — 뭘 주웠느냐에 따라 같은 상황에서 정반대로 움직여야 한다.

효과는 두 갈래로 나뉜다.

- **탄에 실리는 것**(리버스·과충전·펄스) — 내 총이 만드는 폭발의 성질이다. 쏘는 순간
  탄에 도장을 찍고 `bl` 메시지에 실어 보낸다. 상대 화면에서도 같은 성질로 터져야 한다.
  날아가는 도중에 아이템이 끝나도 이미 나간 탄은 원래대로 터진다.
- **몸에 걸리는 것**(깃털·닻·드럼) — 각자 자기 물리를 돌리므로 로컬에만 적용하면 되고
  동기화가 필요 없다.

깃털 글라이딩은 깃털을 주울 때마다 1회 충전된다. 깃털은 원래 "잘 날지만 잘 날아간다"는
양날인데, 날아간 뒤 손쓸 방법이 없어 순수 손해로 느껴질 때가 있었다 — 이 1초가 복귀 수단이다.
글라이딩 중에는 최대 낙하속도가 1.4m/s 로 묶인다(실측: 같은 1초에 일반 낙하 22.2m → 1.4m).

> **패드 내용물과 중재는 서버가 쥔다.** 내용물이 표식으로 미리 보이므로 전원이 같은 걸
> 봐야 하고, 그래서 서버가 정해 `padset` 으로 뿌린다. 밟으면 서버가 "누가 먼저인가"를
> 판정해 저장해 둔 그 아이템을 주고(`pad`), 곧바로 다음 내용물을 굴려 다시 알린다.
> 방에 늦게 들어온 사람도 `join` 시점에 현재 내용물을 전부 받는다.
> `server.js` 의 `ITEM_POOL` 은 `index.html` 의 `ITEMS` 키 목록과 맞춰야 한다.

아이템은 **라운드를 넘기지 못한다**(들고 시작하면 불공평하다). 패드 쿨다운은 서버가
방 단위로 재므로 라운드와 무관하게 흐르고, 새 경기(`start`)에서만 초기화된다.

### 무너지는 바닥 (경쟁 전용)

경기는 **멈추지 않는다.** 누가 떨어지면 점수만 오르고 그 자리에서 바로 부활하며,
먼저 **5점**을 낸 사람이 이긴다. 정산도 라운드 정지도 없다.

**점수는 민 사람에게만 간다.** 최근 6초 안에 맞은 폭발의 주인이 점수를 얻고,
스스로 떨어지면 아무도 못 얻는다(채팅에 `— AI 3` / `(자멸)` 로 표시).

> 예전엔 '떨어진 사람 빼고 전원 +1' 이었다. 1대1 에서는 같은 결과라 문제가 없었는데,
> AI 끼리도 싸우게 되자 **구석에서 구경만 해도 점수가 쌓여 이겼다** —
> 방장을 200m 밖에 세워 두고 20초를 돌리니 5:4 로 승리했다. 지금은 0점이다.

> **리스폰은 발밑이 남아 있는 스폰만 고른다.** 바깥 고리가 무너진 뒤에도 원래 자리로
> 보내면 허공에 떨어져 무한히 실점한다. 전부 사라졌으면 가운데(항상 남는 고리)로 보낸다.

판이 바닥까지 무너지고 5초가 지나면 **새 판이 통째로 깔린다**(`newArena`).
그때도 조작은 멈추지 않는다 — 다만 옛 발판이 사라지므로 위치만 스폰으로 옮겨 준다.

**아레나 바닥은 레벨 파일에 없다.** `collapse` 스펙만 있고 게임이 만들어 깔아준다.
지름 **28.6m**(타일 2.6m, 고리 0~5). 각 타일은 중심에서 몇 번째 고리인지를 들고
있고, 15초 뒤부터 3.6초마다 **바깥 고리부터** 무너진다. 무너지기 1.4초 전에 해당 고리가
주황색으로 깜빡여 예고한다. 가운데 3×3(고리 0·1)은 남겨서 최후의 결전장이 된다.
바닥 위 구조물도 자기 고리와 함께 떨어진다 — 안 그러면 허공에 뜬다.

### 절차적 생성 (`PENG.genArena`)

**라운드마다 판이 새로 만들어진다.** 시드는 세 갈래로 정해진다.

| 상황 | 시드 | 왜 |
|---|---|---|
| 멀티 경기 | 방장이 굴려 `start` 에 실어 보냄 | 전원이 같은 지형을 만들어야 한다 |
| 혼자 플레이 | 시작할 때마다 새로 굴림 | 매번 다른 판 |
| 대기방 연습장 | **방 코드에서 뽑음**(FNV-1a) | 아래 참조 |

각 라운드 시드는 `경기시드 ^ (라운드번호 × 황금비상수)` 다.

> 대기방 연습장 시드를 방 코드에서 뽑는 이유: 대기방에서도 서로가 보이므로 지형이
> 같아야 하는데(안 그러면 상대가 허공에 서 있다), 방마다는 달라야 한다. 방 코드는
> 이미 전원이 공유하고 있어서 **새 메시지 없이** 이 두 조건이 동시에 성립한다.

> **결정론이 전부다.** 릴레이 넷코드라 지형에 권위가 없어서, 각자 굴리면 같은 방인데
> 서로 다른 판에서 싸우게 된다. 그래서 `Math.random()` 을 쓰지 않고 시드를 받아 돌린다.
> 서버가 `start` 를 재구성할 때 `seed` 를 빠뜨리면 이 사고가 그대로 난다(실제로 났다).

> **90도 한 조각만 굴리고 4겹 회전 대칭으로 복제한다.** 밀어 떨어뜨리는 경기에서
> 비대칭은 곧 불공정이다 — 한쪽 스폰만 낭떠러지 옆이면 게임이 망가진다.
> `(i,j) → (-j,i)` 궤도로 묶어 궤도당 한 번만 결정을 내리므로 공정성이 공짜로 따라온다.

연산자(각각 확률로 발동):

| 연산자 | 하는 일 | 왜 |
|---|---|---|
| **해자** | 고리 하나를 비우고 다리 4개만 남김 | 건너는 길이 좁아져 그 위가 곧 승부처 |
| **협곡** | 바깥으로 뻗는 쐐기를 팜 | 안쪽에도 떨어뜨릴 가장자리가 생김 |
| **고지대** | 중간 고리 몇 겹을 1.3m 올림 | 높이 우위와 시야. 점프 도달(1.68m) 안이라 걸어 올라간다 |
| **가장자리 침식** | 바깥 테두리를 들쭉날쭉하게 | 완벽한 원은 인공적으로 보인다 |
| **구조물** | 아래 표의 건축물을 궤도마다 세움 | 격자 발판만으론 건축물이 아니다 |

구조물 5종(각 궤도에 4겹으로 똑같이 선다. 통째로 한 고리에 속해 무너질 때 반쪽만 남지 않는다):

| 구조물 | 생김새 | 쓸모 |
|---|---|---|
| **포탑** | 벽 넷 중 하나를 튼 방 + 옥상(높이 2.6~4.4m) | 옥상이 명당, 안은 엄폐 |
| **계단탑** | 3단으로 줄어드는 층 | 걸어서 올라가는 고지대 |
| **아치** | 기둥 둘 + 상인방 | 밑으로 지나가고 위에 올라선다 |
| **벽** | 긴 판 하나(1.8~2.8m) | 시야 차단, 밀려날 때 걸린다 |
| **고가 발판** | 가느다란 지주 + 3~4.2m 높이 판 | 로켓점프로만 닿는 자리 |

바닥은 **같은 고리·같은 높이의 칸을 최대 직사각형으로 합쳐** 틈 없이 맞물리게 깐다.
낱개 2.6m 정사각형이 낱낱이 깔리면 아무리 파내도 '바둑판'으로 읽힌다. 어느 고리가
무너질지는 예고 깜빡임이 고리 전체를 물들여서 그대로 읽히므로 눈금이 없어도 된다.

> 여러 고리에 걸친 슬랩은 만들지 않는다. 그 고리가 무너질 때 반쪽만 남길 수 없어서
> 통째로 이르게 사라지거나 늦게까지 버티거나 둘 중 하나가 된다.
>
> 스폰·패드는 구조물이 선 궤도를 피한다 — 안 그러면 탑 벽 안에서 시작하거나 패드가 벽에 낀다.
> 구조물의 네 칸은 난수를 한 번만 뽑아 재사용한다. 칸마다 새로 뽑으면 4겹 대칭이 깨져
> 한쪽만 높은 탑이 선다.

생성 후 두 가지를 강제한다.

- **연결성** — 가운데에서 로켓점프(`PENG.reach.rocket`, 안전계수 0.8)로 닿지 않는 조각은
  지운다. 도달 불가 섬이 남으면 거기 떨어진 사람은 아무것도 못 한다.
  지형이 대칭이라 도달 가능성도 대칭이므로 이 정리는 대칭을 깨지 않는다.
- **최소 크기** — 연산자가 겹치면 발판이 20장까지 줄어드는데 그건 아레나가 아니라
  징검다리다. 기준 미달이면 시드를 파생시켜 최대 6번 다시 굴린다(결정론 유지).

고리 0·1 은 어떤 연산자도 건드리지 않는다 — 마지막에 남는 결전장이라 구멍이나 턱이
생기면 싸움이 이상해진다. 스폰(살아남은 가장 바깥 궤도)과 패드도 생성 결과를 따른다.

> 패드 쿨다운은 서버가 방 단위로 재는데 라운드마다 패드 위치가 바뀐다. 라운드가
> 넘어간 직후 최대 12초 동안은 "화면엔 준비인데 서버는 쿨다운"인 패드가 있을 수 있다.
> 밟으면 조용히 빈손이고 그 뒤 저절로 맞춰진다.

> **반경은 "타일 몇 칸"으로 잡아야 한다.** 고리를 반올림 거리로 나누므로 반경이
> 5.0칸이면 바깥 고리가 12장짜리 얇은 테두리가 돼 첫 붕괴가 티도 안 난다.
> 5.5칸(14.3m)이면 28장으로 꽉 찬다.
>
> 발판 위에 놓는 것(단·엄폐물·패드·스폰)은 전부 **타일 중심**(2.6 의 배수)에 맞춘다.
> 경계에 걸치면 그 고리가 무너질 때 절반만 남아 허공에 뜬 것처럼 보인다.
> 스폰은 고리 4, 패드는 고리 3 — 스폰이 첫 붕괴에 쓸려나가지 않는다.

맵을 새로 만들지 않고도 매 라운드 판이 달라지게 하는 게 목적이다. 서로 안 붙고
버티는 교착도 강제로 끝난다. `arena.js` 의 `collapse` 값(`first`·`every`·`radius`)만
바꾸면 속도와 크기가 조절된다.

> 등록된 레벨 데이터(`PENG.levels`)는 원본 그대로 둔다. 붕괴가 boxes 를 실시간으로
> 고치기 때문에 `setLevel` 이 복사본을 만든다 — 안 그러면 한 판 하고 나면 맵이
> 영구히 부서진 채로 남는다.

경쟁에서는 **플레이어끼리 몸이 부딪힌다**(서로 통과하지 못한다). 협동에서는 통과한다 —
좁은 발판 위에서 서로를 실수로 떨어뜨리게 되기 때문이다.

> 릴레이 넷코드라 상대를 직접 밀 수 없다(상대 위치는 그쪽 클라이언트가 정한다).
> 그래서 **양쪽이 각자 자기만 겹친 양의 절반씩** 물러난다. 합치면 정확히 떨어지고
> 한쪽만 튕겨 나가는 비대칭도 안 생긴다. 밀리다 벽에 파고들지 않도록 파고드는 축은 되돌린다.
> 머리 위·발밑처럼 세로로 안 겹치면 통과시킨다(위에서 떨어질 때 끼는 것 방지).

경쟁을 고르면 아레나 맵이 자동으로 선택된다(협동 맵에는 떨어뜨릴 가장자리가 없다).
떨어진 사람이 직접 신고하고 받은 쪽도 같은 규칙을 적용하므로 양쪽 점수가 어긋나지 않는다.

대기방에서 **내 몸통 색**도 고를 수 있다. 고른 색은 저장되고 팀원 화면에도 그대로 보인다.

## 3인칭 카메라 충돌

카메라가 지형을 뚫고 들어가 벽·바닥 안쪽이 보이던 문제를 막는다. 피벗(머리)에서
카메라 자리까지 광선을 쏴 막히면 그 앞까지 당긴다.

- 카메라를 점이 아니라 **반지름 0.25m 인 공**으로 본다 — 박스를 그만큼 부풀려서 쏜다
  (민코프스키 합). 점으로 보면 모서리에서 화면 귀퉁이가 샌다.
- **당길 땐 즉시, 되돌아갈 땐 서서히**(6/초). 한 프레임이라도 뚫리면 안 되지만,
  막힘이 풀릴 때 튕겨 나가면 눈에 거슬린다.
- 피벗이 이미 부풀린 박스 안이면 그 박스는 건너뛴다 — `rayBox` 가 '반대편 출구'를
  돌려줘서 카메라가 벽 너머로 튀어나간다.
- 장식(`deco`)과 꺼진 연동 발판은 카메라도 통과한다(충돌과 같은 기준).

> `aimRay` 는 카메라 중앙축 위의 점에서 광선을 쏘므로 이 변경과 무관하게 조준이
> 유지된다. 오히려 "카메라가 바닥에 파묻혀 코앞에서 막힘이 나오던" 경우가 사라졌다.

디버그 패널 *카메라·조준* 에 충돌 반경 · 최소 거리 · 복귀 속도가 있다.

## 중력 렌즈 (폭발 왜곡)

폭발이 터진 지점이 화면을 잡아당긴다. 장면을 FBO 에 한 번 그린 뒤 전체화면 패스로
UV 를 중심 쪽으로 끌어 샘플링한다. 왜곡원이 하나도 없으면 FBO 를 건너뛴다(평소 비용 0).

- **지형에 가려지면 왜곡하지 않는다.** 카메라에서 폭발 지점과 그 둘레 네 점으로
  광선을 쏴 막힌 비율을 센다. 전부 막히면 버리고, 일부만 막히면 그만큼 약해진다.
  왜곡이 가장 센 중심에 가중치 절반을 준다 — 한가운데가 벽 뒤인 경우가 제일 티나게 뚫려 보인다.
- **화면 크기가 거리에 반비례한다.** 거리 `d` 에서 반지름 `R` 은 화면 높이의
  `0.5*R/(d*tan(fov/2))` 를 덮는다. 예전엔 거리와 무관한 고정 반경이라 30m 밖 폭발도
  코앞처럼 크게 휘어 어디서 터졌는지 알 수 없었다.
- 세기는 반경에 비례하되 **절대 변위 상한**(`LENS_KMAX`)에서 묶인다. 안 그러면
  발밑에서 터지는 로켓점프마다 화면이 30% 가까이 밀려 울렁거린다.

디버그 패널의 *중력 렌즈* 섹션에서 전부 실시간 조절된다.

## 캐릭터 메시 (Kenney Blocky Characters, CC0)

캡슐 대신 `character-d` 를 그린다. 텍스처(`Textures/texture-d.png`)는 굽는 단계에서
정점색에 구워진다(28색).

- 머리·몸통·팔·다리가 **노드로 쪼개진 모델**이라 로더가 노드 계층을 훑어 하나로 합친다.
  첫 노드만 읽으면 몸통 한 조각만 나온다. 애니메이션(27개)은 쓰지 않고 기본 포즈로 굳힌다.
- glTF 규약대로 **−Z 를 본다**(`leg-left`·`arm-left` 가 +X 인 것으로 판정). 게임은 +Z
  전방이라 Z 를 뒤집는 `kenney` 축 매핑을 쓴다.
- 실측 bbox 는 x±0.8 · **y 0~2.7** · z±0.4. 발이 이미 로컬 y=0 이라 `PLAYER_LIFT` 는 **0**,
  배율은 1.8/2.7 = **0.667**(`PLAYER_LIFT` 는 미터가 아니라 모델 로컬 단위다).
- **눈은 따로 그린다.** 시선 추적(`EYE_ROLL`)도 그대로다. 머리가 한 변 0.53m 큐브라
  눈알을 0.115 → **0.065** 로 줄이고 `EYE_Z` 는 머리 앞면(0.267m)보다 살짝 안쪽인 0.22 로 둔다.
- 143정점 / 72삼각형 · 구운 파일 **3KB**.

> **캐릭터는 정적 VBO + 모델행렬로 그린다.** 사람마다 CPU 로 옮기면 프레임을 잡아먹는다
> (앞서 1만 삼각형짜리 모델로 4명일 때 6.3ms → VBO 로 1.4ms).
> 색은 사람마다 다르므로 메인 셰이더에 `uTint` 를 넣고 정점색에는 밝기만 남겼다.
> **툰 윤곽선도 같은 방식**이다 — 법선으로 부풀린 껍질 VBO 를 한 벌 더 만들어,
> 본체를 그린 뒤 `CULL_FACE/BACK` 상태에서 같은 모델행렬로 다시 그린다.

> 다중 노드 모델을 합칠 때 `build()` 안에서 변환 행렬 지역 변수를 `M` 으로 두면
> **모듈 전역 `M`(구운 메시)을 가려서** 마지막 `M={...}` 가 지역 변수에 들어간다.
> 굽기는 되는데 직렬화가 "아직 구운 메시가 없습니다"로 실패한다.

## 총·투사체 메시 (Kenney Blaster Kit, CC0)

에셋 출처: [Kenney](https://kenney.nl) Blaster Kit 2.1 — CC0(퍼블릭 도메인).

총은 `blaster-h`, 투사체는 `bullet-foam-tip-thick` 이다. 원본은 `Mesh/*.glb`(합쳐서 34KB),
게임이 실제로 쓰는 건 구워진 `gunbaked.js`(11KB) · `bulletbaked.js`(2KB) 다.
`<script src>` 로 읽히므로 `file://` 오프라인 플레이에서도 나온다.

모델을 바꾸려면 <http://localhost:8090/tools/bake.html> 에서 대상(총/투사체)을 고르고 굽는다.

> **축 매핑은 굽기 전에 정해야 한다.** 정점 좌표에 그대로 구워지기 때문이다.
> `GunMesh.axes` 가 고른다 — 모델마다 총구가 보는 축이 다르다.
>
> | 이름 | 원본 방향 | 매핑 |
> |---|---|---|
> | `shockwave` | 총구 −X | `(-z, y, -x)` |
> | `kenney` | 총구 −Z | `( x, y, -z)` |
> | `bullet` | 끝이 +Y | `( x, z, y)` — 긴 축을 +Z 로 세운다 |
>
> 셋 다 행렬식이 −1(거울)이라 감기가 한 번 뒤집히고, 인덱스 단계에서 한 번 더 뒤집어
> "바깥면 CW" 규약을 맞춘다. 좌우가 거울로 바뀌지만 총은 좌우 대칭이라 안 보인다.
>
> 새 모델의 방향을 모를 때는 `node tools/inspect_glb.js <파일>` 로 바운딩박스와 축별
> 단면을 본다. 손잡이가 매달린(Y 가 아래로 튀는) 쪽이 뒤, 반대쪽이 총구다.

> **텍스처가 `.glb` 밖에 있을 수 있다.** Kenney 계열은 `Textures/colormap.png` 를
> 상대 경로로 참조한다(`images[0].uri`). 예전 로더는 외부 URI 를 그냥 포기해서
> 총이 통째로 무채색으로 구워졌다 — 저폴리 모델은 **팔레트 텍스처가 곧 생김새**라
> 회색 덩어리로 보인다("모양이 다르다"의 실제 원인이었다).
> 지금은 `.glb` 경로를 기준으로 상대 경로를 풀어 따로 받는다(`data:` URI 도 지원).
> 그래서 `Mesh/Textures/colormap.png` 도 함께 둔다.

**투사체는 총과 다르게 그린다.** 총은 화면에 하나뿐이라 GL 버퍼를 따로 두지만,
탄환은 월드에 여러 개가 동시에 뜬다. 삼각형 44개짜리 작은 메시라 **CPU 로 변환해
기존 삼각형 파이프라인에 밀어 넣는다** — 셰이더도 버퍼도 안 늘어난다.
메시가 로컬 +Z 로 서 있으므로 비행 방향을 +Z 로 두는 정규 직교 기저만 만들면 된다
(수직으로 날 때 축이 퇴화하지 않게 up 벡터를 바꿔 준다).

## 조작

`WASD` 이동 · `마우스` 시점 · `좌클릭` 펑! · `우클릭` 조준 · `Space` 점프 · `F` 펄스 · `R` 리스폰 · `V` 3인칭 · `Enter` 채팅 · `ESC` 일시정지

### 일시정지 (ESC)

`ESC` 를 누르면 **계속하기 / 설정 / 나가기** 메뉴가 뜬다. 뒤가 비쳐서 어디서 멈췄는지 보이고,
아래에 조작표가 함께 뜬다.

> **ESC 는 `keydown` 으로 잡을 수 없다.** 포인터락 중에 ESC 를 누르면 브라우저가 그걸
> '락 해제' 제스처로 먼저 가져가고 페이지에는 키 이벤트를 주지 않는다. 그래서
> `pointerlockchange` 로 "락이 풀렸다"를 일시정지 신호로 쓴다. 알트탭이나 창 밖
> 클릭으로 풀려도 메뉴가 뜨는데, 그건 대부분의 브라우저 FPS 가 하는 동작이라 그대로 뒀다.

- **솔로**: 시간까지 완전히 멈춘다.
- **멀티**: 조작만 막고 물리는 계속 돈다. 다른 사람이 계속 뛰고 있어서 나 혼자
  시간을 세울 수 없다 — 메뉴를 열어둬도 가만히 서 있는 것과 같다(공중이면 떨어진다).
- 디버그 패널은 일시정지 위에 그대로 뜬다(`z-index` 40/41 > 화면 20).

#### 대기방에서는 이 카드가 곧 방 설정판이다

대기방(`lobbyScr`)에도 발밑에 물리가 돌고 마우스가 잠겨 있으므로, 거기서도 `ESC` 의 뜻이
게임 안과 같아야 한다. 예전엔 대기방의 `ESC` 가 **마우스만 풀었고** 화면에는 아무 일도
일어나지 않았다. 그리고 그 빈자리를 안내문 한 줄로 메우고 있었다 —
"Esc 로 마우스를 풀면 버튼을 누를 수 있어요". **문구로 메우고 있는 동작은 대개 빠진 동작이다.**

지금은 같은 메뉴가 뜨고, 그 안에 **방 설정이 통째로 들어 있다**(`#lobbyBlock` —
세션 코드 · 명단 · 맵 · 내 색 · AI · 시작). 제목도 `PAUSED` 대신 `LOBBY` 가 되고,
버튼 이름이 맥락에 맞게 바뀐다(*계속하기* → **연습으로**, *나가기* → **방 나가기**).

> **왜 합쳤나.** 한동안은 대기방 패널이 오른쪽 위에 따로 떠 있었다. 그런데 그 패널은
> 마우스가 풀려 있어야 누를 수 있고, 마우스가 풀리는 순간이 곧 일시정지 메뉴가 뜨는
> 순간이다 — 결국 **언제나 둘이 같이 떠 있었다.** 딤 위로 올릴지 아래로 내릴지,
> 좁은 창에서 어느 쪽이 어느 쪽을 덮는지를 `z-index` 와 미디어 쿼리로 조율하고 있었는데,
> 애초에 두 판이 아니라 한 판이면 조율할 게 없다.

대기방에 들어가면 이 카드가 **먼저 떠 있다**(`enterLobby` → `openPause`). 방을 막 만든
사람이 제일 먼저 할 일이 코드를 알려주고 AI 를 넣는 것이라 그게 첫 화면이어야 한다.
연습은 *연습으로*(또는 `ESC`)로 들어간다.

`lobbyScr` 은 그래서 `SCREENS` 목록에 없다 — `'play'` 처럼 **"화면은 전부 숨김"으로
취급되는 `mode` 값**일 뿐이고, 보이는 것은 일시정지 카드가 전담한다.

> 대기방에서 맵 버튼을 누르면 일시정지를 **접었다가** 시트를 닫을 때 되돌린다
> (`openOverlay('mapScr', 'pause')`). 안 접으면 메뉴가 시트 뒤에 남아 두 겹이 된다.

카드는 `max-height: calc(100vh - 44px)` 로 창에 묶고 안쪽만 스크롤시킨다
(프레임은 제자리에 남는다). 대기방에서는 내용이 길어져 낮은 창에서 *시작* 이
화면 밖으로 밀려나기 때문이다.

### 로켓점프 — 입력 순서는 상관없다

**`Space` 를 먼저 누르든 발밑을 먼저 쏘든 같은 높이로 오른다.**

원래는 아니었다. 폭발은 맞은 사람의 지면 접촉을 지우는데(`onGround=false`, `coyote=0`),
그 때문에 **먼저 쏘면 뒤이어 누른 점프가 통째로 씹혔다.** 실측 도달 높이:

| 입력 순서 | 예전 | 지금 |
|---|---|---|
| 점프 → 사격 | 8.02m | 8.02m |
| 사격 → 점프 | **2.51m** (간격을 아무리 좁혀도) | **8.30m** |

점프에는 선입력 버퍼(`JUMP_BUF`)가 있는데 사격에는 대응물이 없어 생긴 비대칭이었다.
그래서 **`BLAST_JUMP_GRACE`(0.22초)** 를 뒀다 — 땅(또는 코요테 유예) 위에서 폭발에 떠오른 직후
그 시간 안에 누른 점프는 폭발 속도에 **더해진다**. 공중에서 맞은 폭발은 유예를 주지 않으므로
공짜 점프가 생기지는 않고, 최대 도달 높이(`reach.soloRise()` = 8.38m)도 그대로다.

> 두 입력의 간격이 벌어질수록 손해인 건 여전하다(폭발이 발에서 멀어지므로). 다만 예전처럼
> **순서 하나로 69%를 잃는 함정**은 사라졌다. 유예 시간은 디버그 패널의 *폭발 후 점프* 로 조절된다.

### 콘텐츠 브라우저

패널의 아이템을 **뷰포트로 끌어다 놓으면** 배치됩니다. 드롭 지점은 광선이 맞은 발판 윗면,
없으면 바닥 평면입니다. 끄는 동안 놓일 자리가 미리 보입니다.

| 코스 | 협동 | 장식 |
|---|---|---|
| 발판 · 발판(주황) · 결승 발판 · 상자 | 압력판 · 연동 발판 | 나무 · 침엽수 · 바위 · 풀 · 기둥 · 먼 바닥 |

압력판·연동 발판은 **한 쌍**입니다. 놓은 뒤 속성 패널의 **채널**(a~f)로 짝을 맞추세요 —
같은 채널끼리 묶입니다. 왕복 릴레이가 되게 하려면 판을 **협곡 양쪽에 하나씩** 두세요.

나무처럼 여러 박스로 된 프롭은 **하나로 묶여서** 선택·이동·삭제됩니다.

> **장식(`deco`)은 충돌하지 않습니다.** 나무·풀이 보이지 않는 벽이 되면 안 되기 때문입니다.
> 반대로 밟고 올라설 발판은 장식 체크를 꺼야 합니다.

### 구간 자동 배치

`+ 점프` / `+ 로켓` / `+ 협동` 버튼은 마지막(또는 선택한) 발판에서 **그 난이도가 되는 거리**에
새 발판과 체크포인트를 함께 놓습니다. 높이차를 입력하면 그만큼 감안해 거리를 줄입니다.
협동 전용 구간을 손으로 계산할 필요가 없습니다.

> **회전은 지원하지 않습니다.** 게임 충돌이 축 정렬 AABB(`aabbHit`)라서 박스를 돌리면
> 화면만 돌아가고 충돌은 그대로 남습니다 — 보이는 곳에 못 서고 안 보이는 벽에 부딪힙니다.
> 회전을 넣으려면 충돌을 OBB/SAT로 갈아엎어야 하고 기존 발판 감각이 전부 바뀝니다.

### 도달 가능성 분석 — 이 에디터의 핵심

에디터는 게임과 **같은 물리 상수**(`level.js` 의 `PENG.PHYS`)로 협곡마다 넘을 수 있는지 계산해
라벨을 붙입니다. 감으로 배치하고 매번 실행해 볼 필요가 없습니다.

| 라벨 | 뜻 | 평지 기준 한계 |
|---|---|---|
| **점프** | 그냥 점프로 넘어감 | 4.85m |
| **로켓점프** | 자기 발밑을 쏴야 넘어감 | 10.83m |
| **협동 전용** | **혼자서는 불가능** — 팀원이 리프트 샷으로 띄워줘야 넘어감 | 15.90m |
| **협동 관문** | 연동 발판 — 팀원이 압력판을 밟아야 길이 생김 | 간격 무관 |
| **스위치 없음** | 그 채널에 압력판이 없음 → 영영 안 열림 | — |
| **불가능** | 아무도 못 넘음 → 클리어 불가 맵 | — |

높이차가 있으면 한계가 줄어듭니다(예: 3m 올라가야 하면 일반 점프는 아예 불가).

**탑처럼 위로 쌓는 코스**에서는 협곡 길이가 아니라 높이가 난이도를 정합니다. 한 번에 오를 수 있는
최대 높이(수평 이동 0일 때)가 갈림길입니다 — 혼자 **8.38m**(`reach.soloRise()`),
팀원이 띄워주면 **18.08m**(`reach.coopRise()`). **턱이 8.4m를 넘으면 판정에 기대지 않고
물리적으로 혼자서는 불가능**해집니다.
선택한 발판에서 다음 발판 쪽으로 **궤적 3개**(초록=점프 / 주황=로켓 / 하늘=협동)가 그려지므로,
옆에서 보면 어느 방식으로 닿는지 눈으로 확인할 수 있습니다.

패널 맨 아래 판정문이 *"혼자서도 전부 클리어 가능"* 이라고 나오면 2인 게임의 이유가 없는 맵입니다.
**협동 전용 구간을 최소 하나** 넣으세요.

### 저장하는 법

- **▶ 시험 플레이** — 저장 없이 바로 실제 게임으로 확인 (편집본이 그대로 실행됩니다)
- **💾 저장** — `levels/<이름>.js` 에 **바로 기록됩니다.** 게임을 새로고침하면 맵 목록에 뜹니다.
  파일을 옮기거나 HTML 을 고칠 필요가 없습니다.
- **⬇ 다운로드 / 📋 복사** — 서버 없이 쓸 때의 폴백

> 체크포인트를 빠뜨리면 리스폰이 시작점으로 날아갑니다. **체크포인트 자동 생성** 버튼을 쓰세요.

저장은 **서버를 돌리는 PC 에서만** 됩니다. 서버가 `0.0.0.0` 에 열려 있어(친구 LAN 접속용)
누구나 파일을 쓸 수 있으면 안 되기 때문에, `/__save` 는 localhost 요청만 받습니다.
서버가 없으면(`file://` 로 연 경우) 자동으로 다운로드로 떨어집니다.

### 레벨 파일 형식

`levels/*.js` 는 JSON 이 아니라 **고전 `<script>` 로 로드되는 .js** 입니다.
`index.html` 을 더블클릭해서 여는 오프라인 플레이(`file://`)에서 `fetch`/ES 모듈이
CORS 로 막히기 때문입니다. 이 형식을 바꾸면 오프라인 솔로 플레이가 깨집니다.

HTML 이 참조하는 건 **`levels/_all.js` 하나뿐**입니다. 이 파일은 `server.js` 가
`levels/` 폴더를 훑어 자동으로 만들고, 파일이 추가·수정·삭제되면 즉시 다시 만듭니다.
**맵을 추가해도 HTML 을 고칠 일이 없습니다.**

> `_all.js` 는 생성물이지만 **커밋해야 합니다.** 서버를 켜지 않고 `index.html` 을
> 더블클릭해서 여는 사람에게는 이 파일이 이미 있어야 맵이 뜹니다.

```js
PENG.defineLevel('내맵', {
  name: '표시 이름',
  boxes: [
    {cx:0, cy:-0.5, cz:0, hx:3, hy:0.5, hz:3, col:'#5a7bb0'},   // deco:true = 충돌·분석 제외
    {cx:0, cy:0.12, cz:0, hx:1.4, hy:0.12, hz:1.4, plate:'a'},  // 압력판(채널 a)
    {cx:0, cy:9.5, cz:12, hx:3, hy:0.5, hz:3, link:'a'}         // a 를 밟는 동안에만 실체
  ],
  goal: {cx:0, cy:0.5, cz:30, r:3.2},
  checkpoints: [ {x:0, y:0, z:0, gate:true} ],   // gate:true = 여기까지만 되돌린다
  killY: -14, start: {x:0, y:0, z:-2},
  hints: [ '체크포인트 0 에서 뜨는 안내' ]
});
```

> **힌트는 읽고 나면 사라집니다.** 머무는 시간은 글 길이에 맞춥니다
> (`3.5초 + 글자당 0.095초`, 최대 13초 — 태그를 뺀 글자 수로 잽니다).
> 예전엔 한 번 뜨면 그 구간 내내 붙어 있었는데, 아레나는 힌트가 하나뿐이라
> 경기가 끝날 때까지 화면 하단에 띠가 남았습니다. 규칙을 아는 사람에게 그건
> 정보가 아니라 시야를 가리는 물건입니다. 체크포인트를 넘어 새 힌트가 나오면 다시 뜹니다.

`levels/spire.js`(**첨탑**)가 이 기믹을 다 쓰는 예시입니다 — 33발판·높이 120m의 나선 탑에
협동 관문 6개(리프트 샷 3 · 압력판 다리 3), 관문마다 `gate` 체크포인트. 에디터의
`level.js` API 를 그대로 써서 생성했습니다.

메인 메뉴의 맵 선택은 **혼자 플레이 전용**입니다. 방(멀티) 맵은 오직 대기방 선택만 정합니다 —
예전엔 한 변수를 공유해서 메인 메뉴에서 고른 맵이 방 맵까지 바꿨고, 대기방에도 선택이 있어
어느 쪽이 진짜인지 헷갈렸습니다.

멀티에서는 **호스트가 고른 맵**으로 전원이 함께 시작합니다(게스트의 맵 선택은 잠깁니다).
상대에게 없는 맵이면 기본 맵으로 떨어집니다.

## 3D 메시 넣기 (.glb)

메시로 그리는 것은 세 가지입니다.

- **총** — 원래 박스 5개(`index.html` 의 `GUN`)였고 지금은 `Mesh/ShockWave_Gun.glb` 입니다.
- **아이템 표식** — 패드 위에 떠 있는 것. 원래 작은 큐브 몇 개(`ITEMS` 의 `glyph`)였고
  지금은 **음식** 6종입니다(`Mesh/kenney_food-kit/`, CC0). 능력마다 하나씩 골랐습니다 —
  과충전은 버거, 닻은 통햄, 깃털은 바나나, 드럼 탄창은 서브, 리버스캡슐은 크루아상,
  펄스는 계란초밥. 무엇이 무엇인지는 `tools/bakefood.js` 의 `MAP` 한 곳에만 있습니다.
- **플레이어 캐릭터** — 원래 캡슐 + 구체 눈이었고 지금은 `Mesh/SK_Player.glb`
  (리깅 + 걷기 애니메이션)입니다. **이것만 파이프라인이 다릅니다** — 아래를 보세요.

렌더러에 **외부 라이브러리가 없으므로**(three.js 없음) `.glb` 를 직접 읽습니다.

| 파일 | 역할 |
|---|---|
| `Mesh/*.glb` | 원본 모델. **소스일 뿐** — 게임은 평소에 안 읽습니다 |
| `meshlib.js` | .glb 파서 + 정점색 굽기 + GPU 버퍼. **총·아이템이 공유**, 파서는 캐릭터도 씁니다 |
| `gunmesh.js` | 총에만 있는 것 — 조준 기저 배치(크기·위치), 반동, 총구 |
| `itemmesh.js` | 아이템에만 있는 것 — 6종 목록, 크기 정규화, Y축 회전 |
| `charmesh.js` | 캐릭터에만 있는 것 — 스킨 읽기, 포즈 굽기, **전용 셰이더**(텍스처 + GPU 스키닝) |
| `gunbaked.js` | 구워진 총 정점 190KB. **게임이 실제로 쓰는 것** |
| `itembaked.js` | 구워진 아이템 6종 46KB. **게임이 실제로 쓰는 것** |
| `charbaked.js` | 구워진 캐릭터 440KB(정점 + 걷기 포즈 + 1024 텍스처). **게임이 실제로 쓰는 것** |
| `tools/bake.html` | 굽는 도구 (브라우저) — 총·캐릭터 |
| `tools/bakefood.js` | 굽는 도구 (터미널) — 아이템 6종의 메시와 HUD 아이콘 |
| `tools/inspect_glb.js` | 모델 훑어보기 (터미널) |

> 파서를 총·아이템이 나눠 갖는 이유는 단순합니다 — 두 벌 들고 있으면 버그도 두 번 고쳐야
> 합니다. `meshlib.js` 의 `Res` 하나가 '메시 한 개'이고, 나머지 두 파일은 그걸 **어디에
> 어떻게 놓느냐**만 답니다.

### 아이템 표식은 구운 데이터만 씁니다 (그리고 터미널에서 굽습니다)

총은 `gunbaked.js` 가 없으면 원본 `.glb`(6MB)를 받아 그 자리에서 굽습니다.
**아이템은 그러지 않습니다.** 브라우저 굽기(`tools/bake.html`)도 안 씁니다 —
음식 킷이 `meshlib.js` 의 로더가 못 읽는 두 가지를 쓰기 때문입니다.

- **한 파일에 메시가 여럿입니다.** 버거는 빵 위·아래·패티·치즈·양상추·토마토 6조각이고
  서브는 7조각입니다. `Res.build` 는 `meshes[0]` 의 첫 프리미티브만 굽습니다 → 아랫빵만 나옵니다.
- **텍스처가 GLB 밖에 있습니다**(`Textures/colormap.png`). `Res.load` 는 외부 URI 이미지를
  건너뛰고 무채색으로 굽습니다 → 팔레트가 곧 생김새인 킷이라 회색 덩어리가 됩니다.

그래서 `tools/bakefood.js`(Node)가 씬 그래프를 훑어 조각을 전부 합치고, `colormap.png` 를
직접 읽어 정점색에 굽습니다. 결과 형식은 `meshlib.js` 의 `Res.toBaked` 와 같아서
게임 쪽 코드는 그대로입니다.

```bash
node tools/bakefood.js           # itembaked.js + itemicons.js 를 함께 굽는다
```

합칠 때 **겹친 삼각형은 버립니다**. 조각이 맞닿는 자리(아랫빵 윗면 = 패티 밑면)에 같은
삼각형이 두 번 있어서, 깊이가 완전히 같아 화면에서 픽셀마다 이기는 쪽이 갈려 얼룩이 집니다
(버거 78개 · 서브 126개). 두 솔리드 사이에 낀 면이라 어느 쪽을 남겨도 밖에서는 안 보입니다.

`itembaked.js` 가 없거나 일부 종이 빠지면 **그 종만 예전 큐브 표식으로 떨어집니다**
(`ITEMS` 의 `glyph` 는 지워지지 않았습니다). 디버그 패널의 *아이템 표식 메시* → **메시 쓰기**
를 0 으로 두면 메시가 있어도 큐브를 봅니다 — 둘을 나란히 비교할 때 씁니다.

**크기는 배율이 아니라 '가장 긴 변의 길이'로 잡습니다.** 음식마다 비율이 제각각이라
(바나나는 길쭉하고 초밥은 작습니다) 같은 배율을 곱하면 패드마다 표식 크기가 들쭉날쭉해
보입니다. `ItemMesh.SIZE`(기본 0.42m)에 맞춰 메시마다 따로 환산합니다.
**중심도 굽는 쪽에서 원점으로 옮깁니다** — 이 킷은 바닥(Y=0)이 원점이라 그대로 두면
표식이 패드 위로 붕 뜹니다.

### 플레이어 캐릭터만 다른 길로 갑니다 (스킨 + 텍스처)

총·아이템은 텍스처를 **정점색에 구워** 정적 VBO 하나로 그립니다. 캐릭터에 그대로 쓰면
두 가지가 무너집니다.

1. 정점이 6,205개뿐이라 **얼굴이 뭉개집니다.** 굽기는 정점 단위라 텍스처보다 훨씬 성깁니다.
2. 뼈대가 움직이면 정점이 옮겨가는데 **구워둔 명암은 원래 자리의 것**이라 안 따라옵니다.

그래서 캐릭터만 `charmesh.js` 의 전용 셰이더를 씁니다 — 텍스처를 그대로 샘플링하고,
스키닝(본 15개)과 음영을 GPU 에서 계산합니다. 나머지 파이프라인은 손대지 않았습니다.

- **포즈는 미리 굽습니다.** 매 프레임 노드 계층을 훑는 대신 굽는 시점에 24fps 로 한 바퀴를
  떠서 `(프레임 × 본 × 4x3)` 로 저장합니다 — 22프레임 × 15본 = 16KB 입니다. 런타임에 남는
  일은 두 프레임 사이 보간뿐이고, 그 결과를 uniform 으로 올립니다(플레이어당 드로우콜 1개).
- **걷기 위상은 이동 거리로 돕니다**(시간이 아니라). 그래야 발이 안 미끄러집니다.
  네트워크로 보내지 않고 각자 화면에서 위치 변화로 뽑으므로 원격 플레이어도 같이 걷습니다.
  멈추면 `CharMesh.stride`(기본 1.5m/주기) 기준으로 위상이 멈추고 바인드 포즈로 돌아갑니다.
- **팀 색은 텍스처 위에 살짝만 섞습니다**(`CharMesh.tint`, 기본 0.40). 1 로 올리면 색만 남고
  그림이 죽고, 0 이면 누가 누군지 구분이 안 됩니다.
- **눈은 이제 텍스처에 있습니다.** 캡슐 시절의 구체 눈(흰자 + 굴러가는 눈동자)은 메시를 쓸 때
  건너뜁니다 — 얹으면 얼굴 위에 눈이 두 쌍이 됩니다. `CHARMESH_ON=0` 이면 통째로 예전
  캡슐 캐릭터로 떨어집니다(디버그 패널 → *캐릭터 메시(.glb)* → **메시 쓰기**).
- **총은 팔에 안 붙습니다.** 이 리그에는 팔 본이 없어서(척추 7 + 골반 2 + 다리 6) 총은
  예전처럼 조준 기저에 붙습니다. 다만 몸이 캡슐(0.7m)보다 굵어(0.85m) 3인칭 위치를
  `GUN_TP_CHAR` 로 따로 잡아 실루엣 바깥에 걸치게 합니다.

> **애니메이션이 하나뿐입니다.** `Walk` 만 있고, 그중 실제로 키가 찍힌 채널은 `thigh.L/R` 의
> 회전 둘뿐입니다(나머지 43채널은 키 2개짜리 상수). 그래서 무릎·발·척추가 안 접히고 다리가
> 고관절에서 통짜로 흔들립니다. 블렌더에서 `shin`·`foot` 에 키를 얹고 다시 구우면
> 코드는 그대로 두고도 좋아집니다. 대기·점프 동작이 생기면 `charmesh.js` 의 포즈 배열을
> 클립별로 늘리면 됩니다(지금은 `Walk` 한 벌 + 바인드 포즈).

### 새 모델로 바꾸는 순서

**1. 축이 어느 쪽인지 본다** — 터미널에서는 모델을 못 보므로 실루엣을 뽑습니다.

```bash
node tools/inspect_glb.js Mesh/새모델.glb
```

정점 수·바운딩박스·축별 단면표를 찍고, 같은 폴더에 `view_XY.png` · `view_XZ.png` ·
`view_ZY.png`(와이어프레임 실루엣, **빨간 십자 = 원점**)와 `basecolor.jpg` 를 남깁니다.
그림을 보면 총구가 어느 축의 +/− 인지 바로 판단됩니다.

**2. 축 변환을 모델에 맞춘다** — `meshlib.js` 맨 아래의 표 중 하나를 고르거나 새로 만듭니다.
형식은 `[[출처축, 부호], ...]` 로 결과의 x,y,z 순입니다.

```js
var AXIS_FLIP_Z = [[0,1],[1,1],[2,-1]];    // local = ( x, y, -z) — 방향성 없는 모델
var AXIS_GUN    = [[2,-1],[1,1],[0,-1]];   // local = (-z, y, -x) — 총구가 -X 인 총
```

쓰는 쪽에서 `new MeshLib.Res(이름, 축)` 에 넘깁니다. 아이템 6종은 Y-up 이라 방향을
맞출 게 없어 기본 변환만 씁니다(중심 옮기기는 굽는 쪽이 합니다).

**3. 굽는다** — 총·캐릭터는 서버를 켜고 <http://localhost:8090/tools/bake.html> →
총은 경로 입력 후 **굽고 저장**, 캐릭터는 **캐릭터 굽고 저장**. 결과가 `gunbaked.js` ·
`charbaked.js` 로 바로 기록되고, 페이지 아래 미리보기에서 회전시켜 확인할 수 있습니다
(캐릭터는 제자리걸음을 합니다).
**아이템은 터미널입니다** — `node tools/bakefood.js`(위 [아이템 표식은 구운 데이터만
씁니다](#아이템-표식은-구운-데이터만-씁니다-그리고-터미널에서-굽습니다) 참고).

**4. 크기·위치를 맞춘다** — 게임을 새로고침하고 우상단 **DEBUG** → **총 메시(.glb)** /
**아이템 표식 메시(.glb)** / **캐릭터 메시(.glb)** 섹션에서 슬라이더로 맞춥니다. 마음에 드는
값이 나오면 `gunmesh.js` 의 `scale`·`ox`·`oy`·`oz`, `itemmesh.js` 의 `SIZE`,
`charmesh.js` 의 `scale`·`foot`·`tint`·`stride` 기본값에 적어 넣으세요
(패널 값은 저장되지 않습니다).

**5. `*baked.js` 를 커밋한다.** `Mesh/*.glb` 는 `.gitignore` 에 있습니다 — 없어도 게임은 돌고,
다시 구울 때만 필요합니다.

### 축 — 제일 자주 틀리는 곳

glTF 는 **오른손**(+X 오른쪽 · +Y 위 · +Z 뒤), 이 게임은 **왼손**(+Z 앞)입니다.
총 모델은 총구가 −X, 위가 +Y 라서 `local = (-z, y, -x)` 로 옮깁니다.

> **행렬식이 반드시 −1 이어야 합니다.** 이 게임의 메시(캡슐·구·박스)는 '바깥면이 CW' 규약이고
> 윤곽선 껍질이 그걸 전제로 BACK 을 컬링하는데, `build()` 의 감기 뒤집기가 그 전제 위에
> 맞춰져 있습니다. 행렬식이 +1 인 축(예: 축을 두 번 뒤집는 것)을 쓰면 껍질에서 가까운 면이
> 살아남아 메시를 통째로 검게 덮습니다.

> 오른손 → 왼손 변환은 **행렬식이 −1** 이어야 합니다. 축을 짝수 번 바꾸면(행렬식 +1)
> 모델이 **거울상**이 됩니다. 대칭인 총은 티가 잘 안 나지만 텍스처의 글자가 뒤집힙니다.

### 감기 방향(winding)

이 게임의 메시(캡슐·구·박스)는 **바깥면이 CW** 규약이고, 툰 윤곽선이 그걸 전제로
`BACK` 을 컬링합니다. glTF 는 바깥면이 CCW 라서 `build()` 에서 인덱스를 뒤집습니다.

> **총이 통째로 새까맣게 나오면** 십중팔구 이것입니다. 윤곽선 껍질에서 가까운 면이
> 살아남아 본체를 덮은 것이지, 색이 안 구워진 게 아닙니다.
> 확인: 콘솔에서 `GunMesh.outlineW = 0` — 색이 제대로 보이면 감기 문제가 맞습니다.

### 지원 범위

- 삼각형 프리미티브 **1개**만 씁니다(`meshes[0]` 의 첫 삼각형 프리미티브).
- 정점 **65,535개 이하** — 인덱스가 uint16 입니다. 넘으면 로드가 거부되고 박스 총으로 떨어집니다.
- 텍스처는 **베이스컬러만** 씁니다. 노멀맵·러프니스는 안 읽습니다.

총·아이템(`meshlib.js`)에만 해당:

- **스킨·애니메이션은 무시**합니다. 노드 변환(행렬 또는 TRS)은 하나만 적용합니다.
- 텍스처는 긴 변 1024 로 줄여서 정점마다 UV 로 한 번 샘플링해 정점색에 굽습니다.

캐릭터(`charmesh.js`)에만 해당:

- 스킨 **1개**, 본 **64개 이하**(uniform 한도), 애니메이션은 **첫 클립 하나**만 읽습니다.
- 보간은 `LINEAR`·`STEP` 을 지원하고 회전은 구면 보간합니다. `CUBICSPLINE` 은 접선을 버리고
  `LINEAR` 로 낮춥니다.
- 텍스처는 1024 정사각 JPEG 로 다시 뽑아 **데이터 URI 로 함께 저장**합니다(굽지 않습니다).

### 왜 이렇게 만들었나

- **텍스처를 정점색에 굽는다** — 셰이더를 늘리지 않고 캐릭터(캡슐)와 같은 정점색 파이프라인에
  그대로 얹힙니다. 툰 윤곽선(법선으로 부풀린 껍질)도 같은 방식으로 붙습니다.
- **정적 VBO + 모델행렬** — 1만 삼각형을 매 프레임 CPU 로 옮길 수는 없습니다. 한 번만 올리고
  `VP×M` 만 바꿔 그립니다.
- **굽기를 브라우저가 한다** — Node 에는 JPEG 디코더가 없습니다. 새 의존성을 넣는 대신
  브라우저 디코더를 쓰고, 서버는 결과를 `/__bake` 로 받아 파일로 쓰기만 합니다(localhost 전용).
- **`gunbaked.js` 는 `<script src>`** — `levels/_all.js` 와 같은 이유입니다. `fetch` 가 필요 없어야
  `index.html` 을 더블클릭한 오프라인 플레이에서도 총 메시가 나옵니다.

### 안 될 때

| 증상 | 원인 |
|---|---|
| 총이 새까맣다 | 감기 방향 — 위 항목 참고 |
| 좌우가 뒤집혔다 | 축 변환의 행렬식이 +1 |
| 박스 총이 나온다 | 콘솔의 `[gunmesh]` 줄을 보세요. `file://` 인데 `gunbaked.js` 가 없으면 **정상 폴백**입니다 |
| 총구 섬광이 엉뚱한 곳 | `GunMesh.muzzle` 은 **z 최대쪽 2% 정점의 평균**입니다. 총열이 +z 가 아니면 축 변환이 틀린 것 |
| 모델을 바꿨는데 그대로 | 다시 굽지 않았습니다 (`tools/bake.html`). 게임은 `gunbaked.js` 만 봅니다 |
| 굽기 저장이 403 | 서버를 돌리는 PC 에서만 저장됩니다(`/__save` 와 같은 이유) |

메시를 아예 끄고 원래 박스 총으로 보려면 디버그 패널의 **메시 쓰기** 를 0 으로 두면 됩니다.

## HUD 아이콘 굽기 (.png)

아이템 HUD 의 아이콘은 원래 이모지(`🌀💥🥁🪶⚓⚡`)였고 지금은 그림입니다.
킷이 들고 있는 **미리보기 렌더**(`Previews/*.png`)를 그대로 씁니다 — 패드 위 표식과
**같은 모델에서 나온 것**이라, 패드에서 본 물건을 HUD 에서 바로 알아봅니다.

| 파일 | 역할 |
|---|---|
| `Mesh/kenney_food-kit/Previews/*.png` | 원본 미리보기(64×64). **소스일 뿐** — 게임은 안 읽습니다 |
| `itemicons.js` | 구워진 64px 아이콘(data URI) 30KB. **게임이 실제로 쓰는 것** |
| `tools/bakefood.js` | 굽는 도구 (터미널) — 메시와 **같은 실행에서 함께** 굽습니다 |

```bash
node tools/bakefood.js           # itembaked.js + itemicons.js
```

메시(`.glb`)와 달리 **브라우저가 필요 없습니다.** 이 그림들은 PNG 라서 `zlib` 만으로
읽힙니다. 다만 팔레트 PNG(`colorType 3`)라 `PLTE`·`tRNS` 를 풀어 RGBA 로 되돌립니다 —
킷의 `colormap.png` 도 같은 형식이라 디코더 하나를 둘이 씁니다.

굽기가 하는 일은 두 가지뿐입니다.

1. **자르기** — 알파가 있는 픽셀에 맞춰 정사각형으로 자릅니다(여백 4%).
   배경은 `tRNS` 로 이미 뚫려 있어 빼낼 게 없습니다.
2. **줄이기** — 64px 로 맞춥니다. 원본이 64px 이라 배율은 1 근처입니다 — 키워봐야
   흐려지기만 하므로 HUD 표시 크기(22px)에 맞춰 그대로 둡니다.
   알파를 곱한 상태로 평균 내야 투명한 픽셀의 색이 가장자리로 새지 않습니다.

`itemicons.js` 만 있으면 게임이 돌아가므로 원본 PNG 는 저장소에 없어도 됩니다
(`Mesh/*.glb` 와 같은 구조 — 둘 다 `.gitignore` 에 있습니다).
파일이 통째로 없으면 **이모지로 떨어집니다**(`iconHTML`). 굽기 전이어도 HUD 는 돌아갑니다.

**이모지는 폴백이지 기본이 아닙니다.** 패드 표식(3D 메시) · HUD 아이콘 · 획득 채팅 줄
셋이 전부 같은 그림을 씁니다 — 그래야 패드에서 본 물건을 HUD 와 로그에서 바로 알아봅니다.
활공처럼 패드에 없는 가짜 항목만 그림이 없어 자연히 이모지가 됩니다.

> 한동안 채팅 줄만 이모지를 직접 박아 뒀습니다. 이유가 "텍스트 흐름이라 그림을 끼우면
> 줄 높이가 흔들린다" 였는데, 그건 그림 탓이 아니라 **크기를 안 정해줘서**였습니다.
> 16px 상자(`.cmsg .cic`)에 넣으면 흔들리지 않고, 이모지 폴백도 같은 칸을 씁니다.

`renderChat` 은 사용자 문자열을 `textContent` 로만 넣으므로(채팅은 남의 입력입니다)
아이콘은 `innerHTML` 이 아니라 `chatIconNode()` 가 만든 노드로 붙입니다.
`pushChat` 의 다섯 번째 인자에 아이템 키를 주면 그 줄 앞에 붙습니다.

## UI 에셋 굽기 (uiassets.js)

메뉴가 쓰는 것들 — 폰트·키 아이콘·패널 프레임·커서·버튼 소리 — 은 전부
`uiassets.js` 에 **data URI 로 구워져** 있습니다. 이유는 `itemicons.js` 와 같습니다:
`file://` 로 열면 크롬이 로컬 폰트·오디오 요청을 교차 출처로 보고 막습니다.
이 게임은 더블클릭으로도 돌아가야 합니다.

```bash
node tools/bakeui.js
```

| 전역 | 원본 | 쓰는 곳 |
|---|---|---|
| `UI_FONT` | Kenney Future (.ttf) | 화면 제목·라벨 |
| `UI_KEYS` | Input Prompts Pixel 타일맵 | 일시정지 조작표, 대기방 키 안내 |
| `UI_PANEL` | Space Expansion `panel_glass_screws` | `.panel9` 9-slice 프레임 |
| `UI_CURSOR` / `UI_CURSOR2` | `cursor_a` / `cursor_d` | 메뉴 커서 (기본 / 누를 수 있는 것 위) |
| `UI_SND` | UI Pack `tap-b` · `click-a` · `switch-a` | 스침 · 누름 · 화면 전환 |

전부 Kenney, CC0. 파일이 없으면 각각 **기본 폰트 / 글자 키캡 / 1px 테두리 /
OS 커서 / 무음**으로 조용히 떨어집니다.

### 스프라이트는 원본이 아니라 다시 칠한 것입니다

Kenney UI 는 **밝은 회색 바탕에 쓰라고** 만든 것이라 그대로 얹으면 검은 화면에
흰 판이 뜹니다. 그래서 굽는 김에 어두운 팔레트로 바꿉니다.

다행히 둘 다 **인덱스 PNG**(`colorType 3`)라 픽셀은 손댈 필요가 없습니다 —
`PLTE`·`tRNS` 청크만 갈아 끼우면 그림 전체의 색이 바뀝니다. 압축을 풀 일도 없습니다
(`repalette()`). 패널은 명도를 **뒤집어** '밝은 몸통 + 어두운 테두리'를
'어두운 몸통 + 밝은 테두리'로 만듭니다. 나사·베벨의 미세한 명암 차는 뒤집혀도
그대로 살아 있어서 판이 평평해 보이지 않습니다.

### 버튼은 왜 스프라이트가 아닌가

`button.go` 는 지금도 CSS 입니다(아래에 '입술'이 있는 두툼한 버튼). 스프라이트로
바꾸면 색이 토큰에서 자유롭지 않고, 한글 라벨 길이에 따라 9-slice 를 손봐야 합니다.
**스프라이트가 CSS 를 이기는 자리는 프레임입니다** — 나사·노치처럼 CSS 로는
못 그리는 형태가 거기 있고, 그게 "직접 만든 UI"와 "게임 UI"를 가릅니다.

### 소리는 왜 `<audio>` 가 아닌가

구운 ogg 를 `AudioContext` 로 디코드해 기존 `master` 게인에 물립니다.
`<audio>` 엘리먼트로 틀면 설정의 **볼륨·음소거가 안 먹습니다** — 그쪽은 `master` 를
거치지 않기 때문입니다. 디코드는 비동기라 첫 소리 하나를 놓칠 수 있는데,
버튼은 누르기 전에 반드시 스쳐 지나가므로(`pointerover`) 그때 시작해 두면
누를 때는 이미 준비돼 있습니다.

## UI 문구 규칙

화면에 나가는 글은 **설명문이 아니라 이름표**입니다. 지키는 것 넷:

1. **UI 가 보여줄 수 있는 건 글로 쓰지 않는다.** 버튼에 *방 만들기* 라고 적혀 있으면
   그 밑에 "방을 만들고 친구를 부르세요"를 또 쓰지 않는다.
2. **상태는 표시하고 설명하지 않는다.** "🟢 멀티 서버 준비됨 — 방을 만들거나 코드로
   참가하세요" 대신 점 하나와 `ONLINE`. 왜 안 되는지는 **실제로 눌러 봤을 때만** 말한다
   (`#mapErr`·`#joinErr`). 첫 화면에 `node server.js` 가 떠 있으면 그건 게임 화면이
   아니라 개발 로그다.
3. **종결어미와 줄표를 뺀다.** "…합니다 / …하세요 / …할 수 있어요"와 `—` 남용이
   글을 안내문으로 만든다. 인게임 힌트도 같다: *"이번 협곡은 넓어요! 점프 후 발밑을
   좌클릭해 로켓점프!"* → **"넓다. 점프 뒤 발밑 좌클릭"**.
4. **제목은 영문 워드마크, 한글은 그 아래 한 마디.** 구운 폰트가 라틴 전용(214 글리프)이라
   제목이 한글이면 폰트가 통째로 안 보인다. 예전엔 작은 영문 라벨 위에 큰 한글 제목이라
   Kenney 폰트가 타이틀의 `PENG!` 한 곳에만 나왔다.
