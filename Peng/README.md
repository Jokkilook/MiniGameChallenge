# PENG! — 공기폭발 협동 질주 (프로토타입)

WebGL 3D FPS(외부 라이브러리 없음). PoofGun(공기폭발 총)으로 발밑을 쏴 **로켓점프**로 협곡을 넘어 결승선까지. 솔로 또는 여러 명 협동.

## 혼자 플레이 (오프라인)

`index.html`을 브라우저로 그냥 열면 됩니다. 외부 라이브러리·인터넷 불필요. 멀티는 자동으로 비활성(솔로)로 폴백됩니다.

## 멀티플레이 (세션 코드로 함께)

의존성 0 Node 서버가 포함되어 있습니다. `npm install` 필요 없음.

```bash
node server.js
```

접속: <http://localhost:8090/>

> ⚠️ **반드시 위 주소로 여세요.** `index.html` 파일을 더블클릭해서 열거나(`file://`),
> 다른 정적 서버(예: `python -m http.server`) 주소로 열면 그쪽에는 멀티 서버가 없어
> "멀티 서버에 연결할 수 없습니다"가 뜹니다. 메인 메뉴 하단에 현재 상태
> (🟢 준비됨 / ⚠️ 안내)가 표시되니 확인하고 시작하세요.

### 함께 하는 순서

1. **호스트**: 메인 메뉴에서 **방 만들기** → 6자리 **세션 코드**가 나오고 대기방으로 이동
2. 그 코드를 친구에게 알려줍니다 (대기방의 *코드 복사* 사용)
3. **친구**: 같은 주소로 접속 → **방 참가하기** → 코드 입력 → 대기방 합류
4. 대기방에 2명 이상이 되면 호스트의 **게임 시작** 버튼이 활성화 → 누르면 **전원 동시 시작**

- 포트 변경: `PORT=3000 node server.js`
- 친구가 **다른 PC**에서 들어오려면 같은 공유기라면 호스트 PC의 내부 IP로 접속(`http://192.168.x.x:8090/`),
  인터넷 너머라면 8090 포트 개방 또는 터널(ngrok 등)이 필요합니다.
- 없는 코드를 입력하면 "방을 찾을 수 없어요"로 거부됩니다(빈 방이 생기지 않음).

### 동작 방식 (릴레이 넷코드)

각 클라이언트가 자기 물리를 로컬에서 돌리고, 자기 상태(위치·시점·반동)와 발사한 **폭발(blast)** 만 서버로 보냅니다. 서버는 같은 방의 다른 사람에게 그대로 중계합니다.

- 상대는 **청록 캡슐 + 총**으로 렌더됩니다.
- **핵심 협동**: 팀원이 쏜 펑건 폭발 반경 안에 있으면 **날아갑니다** — 서로 밀어서 협곡을 넘겨주세요!

## 협동 기믹

폭발 넉백은 **방사형**이다(폭발 중심 → 몸). 그래서 원래는 팀원의 **발밑을 받쳐 쏘는** 한 방향만
도움이 됐고, 위에서 아래로 쏘면 팀원이 오히려 처박혔다. 그 결과 협동 전용 구간은 **편도**였다 —
한 명은 넘어가고 남은 한 명은 영영 못 넘는다. 협동 승리는 개인별이라 정말로 한 명만 골인했다.

### 리프트 샷 — 팀원 직격

팀원을 **근접 신관(`FUSE_R` 1.3m) 안으로 직격**하면 방사형 대신 **정확히 위로만** 밀어준다
(`PHYS.LIFT_V`, 기본 9.0m/s · 거리 감쇠 없음). 위에 먼저 올라간 사람이 아래를 향해 쏴서
남은 팀원을 끌어올릴 수 있다 — 이제 도움이 **양방향**이다.

- 직격 폭발은 색이 다르다(연청록). 쏜 쪽이 제대로 맞혔는지 바로 안다.
- **경쟁 모드에서는 꺼진다.** 밖으로 밀어내는 게 목적인데 수직으로만 띄우면 넉백이 죽는다.
- 거리 감쇠를 두지 않은 이유: "팀원이 얼마나 가까이서 쐈나"에 따라 도달거리가 흔들리면
  에디터의 도달 분석을 믿을 수 없게 된다. 고정값이라 설계 숫자가 그대로 맞는다.

### 연동 압력판

`plate:'a'` 를 누군가 **밟고 있는 동안에만** 같은 채널의 `link:'a'` 발판이 실체가 된다
(충돌·광선·발판 전부). 밟는 사람은 건널 수 없으므로, 건너간 사람이 **반대편 판을 밟아
되갚아 주는 왕복 릴레이**가 된다.

상대 위치는 이미 매 프레임 중계되므로 **새 프로토콜이 필요 없다** — 양쪽이 각자 같은 판정을 한다.
꺼진 다리는 지우지 않고 어둡게 남긴다(생길 자리가 보여야 퍼즐이 성립한다).

### 관문 체크포인트

체크포인트에 `gate:true` 를 달면 **거기까지만 되돌린다.** 떨어지면 한 덩어리를 다시 올라가야 한다.
체크포인트 자체는 발판마다 촘촘히 둘 수 있다 — 에디터의 경로 분석이 체크포인트 순서를
따라가므로 촘촘해야 정확하기 때문이다. `gate` 가 없는 맵은 예전대로 마지막 체크포인트로 돌아간다.

## 게임 모드

대기방에서 호스트가 고른다(게스트 쪽은 잠긴다).

| 모드 | 규칙 |
|---|---|
| **협동** | 기존대로 함께 결승선까지. 혼자 못 넘는 협곡은 팀원이 밀어줘야 한다. |
| **경쟁** | 아레나에서 상대를 **밖으로 떨어뜨리면 1점**. 먼저 5점이면 승리. |

### 아이템 패드

아레나 바닥의 **원판 패드**를 밟으면 아이템이 하나 나온다(12초 쿨다운 후 재생성).
원판 지름은 캐릭터 지름(0.7m)과 같고, 몸이 원판에 닿으면 집힌다.
패드는 스폰(반경 6)과 가운데 단(반경 2.2) 사이에 있어서, 집으러 가려면 반드시 자기 자리를
비우고 가운데로 나와야 한다. 고리 2 라서 중반에 무너지고, 후반에는 가운데 단 위 하나만 남는다.

**원판은 어느 패드든 똑같은 색이다.** 무작위인 건 그 위에 떠 있는 **내용물 표식**뿐이다.
아이템마다 모양·색이 달라서 보고 판단해 가져갈지 정하게 된다(자리 싸움이 생긴다).
표식은 작은 큐브 몇 개로 만든다: 회전 메시가 없어서 큐브가 작아야 'Y축으로 도는 궤도'가
어색하지 않고 의도한 것처럼 보인다.

패드는 **세 겹**으로 그린다.

| 겹 | 색 | 역할 |
|---|---|---|
| 기본 바탕 원판 | `#16222f` | 패드 자리 |
| 빈 링 트랙 (항상 한 바퀴) | `#44607d` | 게이지가 찰 자리 |
| 차오른 링 | `#3fe0b4` | 진행도 |

**준비 상태 = 링이 100% 찬 모습**이다. 집어가면 표식이 사라지고 링이 0 부터 다시 찬다.
다 차면 다음 아이템이 나타난다 — 숫자 없이도 "지금 집을 수 있나 · 언제 다시 오면 되나"가
멀리서 읽힌다. 바탕과 빈 트랙은 색이 확실히 달라야 한다(같으면 빈 구간이 바탕에 묻힌다).
세 겹이 같은 높이면 z-파이팅이 나므로 조금씩 띄워 얹는다.

> 스폰 지점은 패드에서 판정 반경 밖으로 떨어뜨려야 한다. 아레나 `start` 가 패드에서
> 0.4m 라 솔로로 들어가면 서자마자 아이템이 주워졌다.

### 아이템 HUD

탄창 위(우하단)에 현재 상태가 뜬다. 두 종류를 구분한다.

- **작동 중**(실선 테두리) — 시간이 흐르는 버프. 아이템 색, 남은 초, 아래에 진행 바.
- **보유 중**(점선 테두리) — 내가 눌러야 나가는 것. 어떤 키인지 같이 뜬다(펄스 `F`, 글라이딩 `Space`).

줄 구성이 바뀔 때만 DOM 을 다시 만들고 평소엔 숫자와 바 길이만 갱신한다 —
매 프레임 `innerHTML` 을 다시 쓰면 레이아웃이 계속 다시 계산된다.

| 아이템 | 효과 | 지속 |
|---|---|---|
| 🌀 **리버스캡슐** | 폭발이 밀어내는 대신 **끌어당긴다**. 상대를 내 쪽 낭떠러지로 당기거나 발판에 매달릴 때. 로켓점프는 못 한다 | 12초 |
| 💥 **과충전** | 폭발 위력 ×1.8 · 반경 ×1.25. 실측 넉백 2.85배 | 12초 |
| 🥁 **드럼 탄창** | 탄창 즉시 충전 + 재장전 3배. 계속 밀어붙이는 용 | 15초 |
| 🪶 **깃털** | 받는 반동 ×1.7 · 중력 ×0.6. **더 멀리 날지만 더 잘 날아간다**. 공중에서 `Space` 한 번 더 → **1초 글라이딩**(1회) | 15초 |
| ⚓ **닻** | 받는 반동 ×0.35. 안 밀린다 — 대신 로켓점프도 약해져 기동을 잃는다 | 10초 |
| ⚡ **펄스** | `F` — 내 주위로 대형 폭발(위력 ×2 · 반경 ×1.6). 붙은 상대를 떼어낸다. 나에게는 안 걸린다 | 1회 |

깃털과 닻이 정반대인 게 핵심이다 — 뭘 주웠느냐에 따라 같은 상황에서 정반대로 움직여야 한다.

효과는 두 갈래로 나뉜다.

- **탄에 실리는 것**(리버스·과충전·펄스) — 내 총이 만드는 폭발의 성질이다. 쏘는 순간
  탄에 도장을 찍고 `bl` 메시지에 실어 보낸다. 상대 화면에서도 같은 성질로 터져야 한다.
  날아가는 도중에 아이템이 끝나도 이미 나간 탄은 원래대로 터진다.
- **몸에 걸리는 것**(깃털·닻·드럼) — 각자 자기 물리를 돌리므로 로컬에만 적용하면 되고
  동기화가 필요 없다.

깃털 글라이딩은 깃털을 주울 때마다 1회 충전된다. 깃털은 원래 "잘 날지만 잘 날아간다"는
양날인데, 날아간 뒤 손쓸 방법이 없어 순수 손해로 느껴질 때가 있었다 — 이 1초가 복귀 수단이다.
글라이딩 중에는 최대 낙하속도가 1.4m/s 로 묶인다(실측: 같은 1초에 일반 낙하 22.2m → 1.4m).

> **패드 내용물과 중재는 서버가 쥔다.** 내용물이 표식으로 미리 보이므로 전원이 같은 걸
> 봐야 하고, 그래서 서버가 정해 `padset` 으로 뿌린다. 밟으면 서버가 "누가 먼저인가"를
> 판정해 저장해 둔 그 아이템을 주고(`pad`), 곧바로 다음 내용물을 굴려 다시 알린다.
> 방에 늦게 들어온 사람도 `join` 시점에 현재 내용물을 전부 받는다.
> `server.js` 의 `ITEM_POOL` 은 `index.html` 의 `ITEMS` 키 목록과 맞춰야 한다.

아이템은 **라운드를 넘기지 못한다**(들고 시작하면 불공평하다). 패드 쿨다운은 서버가
방 단위로 재므로 라운드와 무관하게 흐르고, 새 경기(`start`)에서만 초기화된다.

### 라운드와 무너지는 바닥 (경쟁 전용)

경쟁은 **라운드제**다. 누가 떨어지면 점수가 오르고 2.4초 정산 후 전원이 스폰으로 돌아간다.
정산 중에는 이동·발사가 막힌다 — 안 그러면 스폰 복귀 전에 미리 밀어두는 짓이 된다.
라운드마다 스폰이 한 칸씩 돌아가서 같은 자리만 반복되지 않는다.

> 예전엔 떨어지면 그 자리에서 즉시 리스폰이라 라운드라는 게 없었다. 이긴 쪽이
> 위치와 속도를 그대로 쥔 채 다시 밀어버려 눈덩이가 굴렀고, 한 킬이 성취로 느껴지지도 않았다.

**아레나 바닥은 레벨 파일에 없다.** `collapse` 스펙만 있고 게임이 타일 격자로 깔아준다.
지름 **28.6m**(타일 2.6m × 97장, 고리 0~5). 각 타일은 중심에서 몇 번째 고리인지를 들고
있고, 15초 뒤부터 3.6초마다 **바깥 고리부터** 무너진다(97 → 69 → 37 → 21 → 9 → 1).
무너지기 1.4초 전에 해당 고리가 주황색으로 깜빡여 예고한다.
가운데 단(고리 0)은 남겨서 최후의 결전장이 된다. 바닥 위 구조물도 자기 고리와 함께
떨어진다 — 안 그러면 허공에 뜬다.

> **반경은 "타일 몇 칸"으로 잡아야 한다.** 고리를 반올림 거리로 나누므로 반경이
> 5.0칸이면 바깥 고리가 12장짜리 얇은 테두리가 돼 첫 붕괴가 티도 안 난다.
> 5.5칸(14.3m)이면 28장으로 꽉 찬다.
>
> 발판 위에 놓는 것(단·엄폐물·패드·스폰)은 전부 **타일 중심**(2.6 의 배수)에 맞춘다.
> 경계에 걸치면 그 고리가 무너질 때 절반만 남아 허공에 뜬 것처럼 보인다.
> 스폰은 고리 4, 패드는 고리 3 — 스폰이 첫 붕괴에 쓸려나가지 않는다.

맵을 새로 만들지 않고도 매 라운드 판이 달라지게 하는 게 목적이다. 서로 안 붙고
버티는 교착도 강제로 끝난다. `arena.js` 의 `collapse` 값(`first`·`every`·`radius`)만
바꾸면 속도와 크기가 조절된다.

> 등록된 레벨 데이터(`PENG.levels`)는 원본 그대로 둔다. 붕괴가 boxes 를 실시간으로
> 고치기 때문에 `setLevel` 이 복사본을 만든다 — 안 그러면 한 판 하고 나면 맵이
> 영구히 부서진 채로 남는다.

경쟁에서는 **플레이어끼리 몸이 부딪힌다**(서로 통과하지 못한다). 협동에서는 통과한다 —
좁은 발판 위에서 서로를 실수로 떨어뜨리게 되기 때문이다.

> 릴레이 넷코드라 상대를 직접 밀 수 없다(상대 위치는 그쪽 클라이언트가 정한다).
> 그래서 **양쪽이 각자 자기만 겹친 양의 절반씩** 물러난다. 합치면 정확히 떨어지고
> 한쪽만 튕겨 나가는 비대칭도 안 생긴다. 밀리다 벽에 파고들지 않도록 파고드는 축은 되돌린다.
> 머리 위·발밑처럼 세로로 안 겹치면 통과시킨다(위에서 떨어질 때 끼는 것 방지).

경쟁을 고르면 아레나 맵이 자동으로 선택된다(협동 맵에는 떨어뜨릴 가장자리가 없다).
떨어진 사람이 직접 신고하고 받은 쪽도 같은 규칙을 적용하므로 양쪽 점수가 어긋나지 않는다.

대기방에서 **내 몸통 색**도 고를 수 있다. 고른 색은 저장되고 팀원 화면에도 그대로 보인다.

## 3인칭 카메라 충돌

카메라가 지형을 뚫고 들어가 벽·바닥 안쪽이 보이던 문제를 막는다. 피벗(머리)에서
카메라 자리까지 광선을 쏴 막히면 그 앞까지 당긴다.

- 카메라를 점이 아니라 **반지름 0.25m 인 공**으로 본다 — 박스를 그만큼 부풀려서 쏜다
  (민코프스키 합). 점으로 보면 모서리에서 화면 귀퉁이가 샌다.
- **당길 땐 즉시, 되돌아갈 땐 서서히**(6/초). 한 프레임이라도 뚫리면 안 되지만,
  막힘이 풀릴 때 튕겨 나가면 눈에 거슬린다.
- 피벗이 이미 부풀린 박스 안이면 그 박스는 건너뛴다 — `rayBox` 가 '반대편 출구'를
  돌려줘서 카메라가 벽 너머로 튀어나간다.
- 장식(`deco`)과 꺼진 연동 발판은 카메라도 통과한다(충돌과 같은 기준).

> `aimRay` 는 카메라 중앙축 위의 점에서 광선을 쏘므로 이 변경과 무관하게 조준이
> 유지된다. 오히려 "카메라가 바닥에 파묻혀 코앞에서 막힘이 나오던" 경우가 사라졌다.

디버그 패널 *카메라·조준* 에 충돌 반경 · 최소 거리 · 복귀 속도가 있다.

## 중력 렌즈 (폭발 왜곡)

폭발이 터진 지점이 화면을 잡아당긴다. 장면을 FBO 에 한 번 그린 뒤 전체화면 패스로
UV 를 중심 쪽으로 끌어 샘플링한다. 왜곡원이 하나도 없으면 FBO 를 건너뛴다(평소 비용 0).

- **지형에 가려지면 왜곡하지 않는다.** 카메라에서 폭발 지점과 그 둘레 네 점으로
  광선을 쏴 막힌 비율을 센다. 전부 막히면 버리고, 일부만 막히면 그만큼 약해진다.
  왜곡이 가장 센 중심에 가중치 절반을 준다 — 한가운데가 벽 뒤인 경우가 제일 티나게 뚫려 보인다.
- **화면 크기가 거리에 반비례한다.** 거리 `d` 에서 반지름 `R` 은 화면 높이의
  `0.5*R/(d*tan(fov/2))` 를 덮는다. 예전엔 거리와 무관한 고정 반경이라 30m 밖 폭발도
  코앞처럼 크게 휘어 어디서 터졌는지 알 수 없었다.
- 세기는 반경에 비례하되 **절대 변위 상한**(`LENS_KMAX`)에서 묶인다. 안 그러면
  발밑에서 터지는 로켓점프마다 화면이 30% 가까이 밀려 울렁거린다.

디버그 패널의 *중력 렌즈* 섹션에서 전부 실시간 조절된다.

### 일시정지 (ESC)

게임 중 `ESC` 를 누르면 **계속하기 / 나가기** 메뉴가 뜬다. 뒤가 비쳐서 어디서 멈췄는지 보인다.

> **ESC 는 `keydown` 으로 잡을 수 없다.** 포인터락 중에 ESC 를 누르면 브라우저가 그걸
> '락 해제' 제스처로 먼저 가져가고 페이지에는 키 이벤트를 주지 않는다. 그래서
> `pointerlockchange` 로 "락이 풀렸다"를 일시정지 신호로 쓴다. 알트탭이나 창 밖
> 클릭으로 풀려도 메뉴가 뜨는데, 그건 대부분의 브라우저 FPS 가 하는 동작이라 그대로 뒀다.

- **솔로**: 시간까지 완전히 멈춘다.
- **멀티**: 조작만 막고 물리는 계속 돈다. 다른 사람이 계속 뛰고 있어서 나 혼자
  시간을 세울 수 없다 — 메뉴를 열어둬도 가만히 서 있는 것과 같다(공중이면 떨어진다).
- 대기방(`lobbyScr`)에서는 뜨지 않는다. 그 화면엔 이미 UI 가 있다.
- 디버그 패널은 일시정지 위에 그대로 뜬다(`z-index` 40/41 > 화면 20).

### 로켓점프 — 입력 순서는 상관없다

**`Space` 를 먼저 누르든 발밑을 먼저 쏘든 같은 높이로 오른다.**

원래는 아니었다. 폭발은 맞은 사람의 지면 접촉을 지우는데(`onGround=false`, `coyote=0`),
그 때문에 **먼저 쏘면 뒤이어 누른 점프가 통째로 씹혔다.** 실측 도달 높이:

| 입력 순서 | 예전 | 지금 |
|---|---|---|
| 점프 → 사격 | 8.02m | 8.02m |
| 사격 → 점프 | **2.51m** (간격을 아무리 좁혀도) | **8.30m** |

점프에는 선입력 버퍼(`JUMP_BUF`)가 있는데 사격에는 대응물이 없어 생긴 비대칭이었다.
그래서 **`BLAST_JUMP_GRACE`(0.22초)** 를 뒀다 — 땅(또는 코요테 유예) 위에서 폭발에 떠오른 직후
그 시간 안에 누른 점프는 폭발 속도에 **더해진다**. 공중에서 맞은 폭발은 유예를 주지 않으므로
공짜 점프가 생기지는 않고, 최대 도달 높이(`reach.soloRise()` = 8.38m)도 그대로다.

> 두 입력의 간격이 벌어질수록 손해인 건 여전하다(폭발이 발에서 멀어지므로). 다만 예전처럼
> **순서 하나로 69%를 잃는 함정**은 사라졌다. 유예 시간은 디버그 패널의 *폭발 후 점프* 로 조절된다.

### 콘텐츠 브라우저

패널의 아이템을 **뷰포트로 끌어다 놓으면** 배치됩니다. 드롭 지점은 광선이 맞은 발판 윗면,
없으면 바닥 평면입니다. 끄는 동안 놓일 자리가 미리 보입니다.

| 코스 | 협동 | 장식 |
|---|---|---|
| 발판 · 발판(주황) · 결승 발판 · 상자 | 압력판 · 연동 발판 | 나무 · 침엽수 · 바위 · 풀 · 기둥 · 먼 바닥 |

압력판·연동 발판은 **한 쌍**입니다. 놓은 뒤 속성 패널의 **채널**(a~f)로 짝을 맞추세요 —
같은 채널끼리 묶입니다. 왕복 릴레이가 되게 하려면 판을 **협곡 양쪽에 하나씩** 두세요.

나무처럼 여러 박스로 된 프롭은 **하나로 묶여서** 선택·이동·삭제됩니다.

> **장식(`deco`)은 충돌하지 않습니다.** 나무·풀이 보이지 않는 벽이 되면 안 되기 때문입니다.
> 반대로 밟고 올라설 발판은 장식 체크를 꺼야 합니다.

### 구간 자동 배치

`+ 점프` / `+ 로켓` / `+ 협동` 버튼은 마지막(또는 선택한) 발판에서 **그 난이도가 되는 거리**에
새 발판과 체크포인트를 함께 놓습니다. 높이차를 입력하면 그만큼 감안해 거리를 줄입니다.
협동 전용 구간을 손으로 계산할 필요가 없습니다.

> **회전은 지원하지 않습니다.** 게임 충돌이 축 정렬 AABB(`aabbHit`)라서 박스를 돌리면
> 화면만 돌아가고 충돌은 그대로 남습니다 — 보이는 곳에 못 서고 안 보이는 벽에 부딪힙니다.
> 회전을 넣으려면 충돌을 OBB/SAT로 갈아엎어야 하고 기존 발판 감각이 전부 바뀝니다.

### 도달 가능성 분석 — 이 에디터의 핵심

에디터는 게임과 **같은 물리 상수**(`level.js` 의 `PENG.PHYS`)로 협곡마다 넘을 수 있는지 계산해
라벨을 붙입니다. 감으로 배치하고 매번 실행해 볼 필요가 없습니다.

| 라벨 | 뜻 | 평지 기준 한계 |
|---|---|---|
| **점프** | 그냥 점프로 넘어감 | 4.85m |
| **로켓점프** | 자기 발밑을 쏴야 넘어감 | 10.83m |
| **협동 전용** | **혼자서는 불가능** — 팀원이 리프트 샷으로 띄워줘야 넘어감 | 15.90m |
| **협동 관문** | 연동 발판 — 팀원이 압력판을 밟아야 길이 생김 | 간격 무관 |
| **스위치 없음** | 그 채널에 압력판이 없음 → 영영 안 열림 | — |
| **불가능** | 아무도 못 넘음 → 클리어 불가 맵 | — |

높이차가 있으면 한계가 줄어듭니다(예: 3m 올라가야 하면 일반 점프는 아예 불가).

**탑처럼 위로 쌓는 코스**에서는 협곡 길이가 아니라 높이가 난이도를 정합니다. 한 번에 오를 수 있는
최대 높이(수평 이동 0일 때)가 갈림길입니다 — 혼자 **8.38m**(`reach.soloRise()`),
팀원이 띄워주면 **18.08m**(`reach.coopRise()`). **턱이 8.4m를 넘으면 판정에 기대지 않고
물리적으로 혼자서는 불가능**해집니다.
선택한 발판에서 다음 발판 쪽으로 **궤적 3개**(초록=점프 / 주황=로켓 / 하늘=협동)가 그려지므로,
옆에서 보면 어느 방식으로 닿는지 눈으로 확인할 수 있습니다.

패널 맨 아래 판정문이 *"혼자서도 전부 클리어 가능"* 이라고 나오면 2인 게임의 이유가 없는 맵입니다.
**협동 전용 구간을 최소 하나** 넣으세요.

### 저장하는 법

- **▶ 시험 플레이** — 저장 없이 바로 실제 게임으로 확인 (편집본이 그대로 실행됩니다)
- **💾 저장** — `levels/<이름>.js` 에 **바로 기록됩니다.** 게임을 새로고침하면 맵 목록에 뜹니다.
  파일을 옮기거나 HTML 을 고칠 필요가 없습니다.
- **⬇ 다운로드 / 📋 복사** — 서버 없이 쓸 때의 폴백

> 체크포인트를 빠뜨리면 리스폰이 시작점으로 날아갑니다. **체크포인트 자동 생성** 버튼을 쓰세요.

저장은 **서버를 돌리는 PC 에서만** 됩니다. 서버가 `0.0.0.0` 에 열려 있어(친구 LAN 접속용)
누구나 파일을 쓸 수 있으면 안 되기 때문에, `/__save` 는 localhost 요청만 받습니다.
서버가 없으면(`file://` 로 연 경우) 자동으로 다운로드로 떨어집니다.

### 레벨 파일 형식

`levels/*.js` 는 JSON 이 아니라 **고전 `<script>` 로 로드되는 .js** 입니다.
`index.html` 을 더블클릭해서 여는 오프라인 플레이(`file://`)에서 `fetch`/ES 모듈이
CORS 로 막히기 때문입니다. 이 형식을 바꾸면 오프라인 솔로 플레이가 깨집니다.

HTML 이 참조하는 건 **`levels/_all.js` 하나뿐**입니다. 이 파일은 `server.js` 가
`levels/` 폴더를 훑어 자동으로 만들고, 파일이 추가·수정·삭제되면 즉시 다시 만듭니다.
**맵을 추가해도 HTML 을 고칠 일이 없습니다.**

> `_all.js` 는 생성물이지만 **커밋해야 합니다.** 서버를 켜지 않고 `index.html` 을
> 더블클릭해서 여는 사람에게는 이 파일이 이미 있어야 맵이 뜹니다.

```js
PENG.defineLevel('내맵', {
  name: '표시 이름',
  boxes: [
    {cx:0, cy:-0.5, cz:0, hx:3, hy:0.5, hz:3, col:'#5a7bb0'},   // deco:true = 충돌·분석 제외
    {cx:0, cy:0.12, cz:0, hx:1.4, hy:0.12, hz:1.4, plate:'a'},  // 압력판(채널 a)
    {cx:0, cy:9.5, cz:12, hx:3, hy:0.5, hz:3, link:'a'}         // a 를 밟는 동안에만 실체
  ],
  goal: {cx:0, cy:0.5, cz:30, r:3.2},
  checkpoints: [ {x:0, y:0, z:0, gate:true} ],   // gate:true = 여기까지만 되돌린다
  killY: -14, start: {x:0, y:0, z:-2},
  hints: [ '체크포인트 0 에서 뜨는 안내' ]
});
```

`levels/spire.js`(**첨탑**)가 이 기믹을 다 쓰는 예시입니다 — 33발판·높이 120m의 나선 탑에
협동 관문 6개(리프트 샷 3 · 압력판 다리 3), 관문마다 `gate` 체크포인트. 에디터의
`level.js` API 를 그대로 써서 생성했습니다.

메인 메뉴의 맵 선택은 **혼자 플레이 전용**입니다. 방(멀티) 맵은 오직 대기방 선택만 정합니다 —
예전엔 한 변수를 공유해서 메인 메뉴에서 고른 맵이 방 맵까지 바꿨고, 대기방에도 선택이 있어
어느 쪽이 진짜인지 헷갈렸습니다.

멀티에서는 **호스트가 고른 맵**으로 전원이 함께 시작합니다(게스트의 맵 선택은 잠깁니다).
상대에게 없는 맵이면 기본 맵으로 떨어집니다.

| `Mesh/*.glb` | 원본 모델. **소스일 뿐** — 게임은 평소에 안 읽습니다 |
| `gunbaked.js` | 구워진 정점(위치·색·법선·인덱스) 190KB. **게임이 실제로 쓰는 것** |
| `gunmesh.js` | .glb 파서 + 굽기 + 그리기. 배치값(크기·위치)의 기본값도 여기 맨 위 |
| `tools/bake.html` | 굽는 도구 (브라우저) |
| `tools/inspect_glb.js` | 모델 훑어보기 (터미널) |

### 새 모델로 바꾸는 순서

**1. 축이 어느 쪽인지 본다** — 터미널에서는 모델을 못 보므로 실루엣을 뽑습니다.

```bash
node tools/inspect_glb.js Mesh/새모델.glb
```

정점 수·바운딩박스·축별 단면표를 찍고, 같은 폴더에 `view_XY.png` · `view_XZ.png` ·
`view_ZY.png`(와이어프레임 실루엣, **빨간 십자 = 원점**)와 `basecolor.jpg` 를 남깁니다.
그림을 보면 총구가 어느 축의 +/− 인지 바로 판단됩니다.

**2. `gunmesh.js` 의 축 변환을 모델에 맞춘다** — `build()` 안의 이 줄입니다.

```js
var lx = -q[2], ly = q[1], lz = -q[0];   // local = (-z, y, -x)
```

**3. 굽는다** — 서버를 켜고 <http://localhost:8090/tools/bake.html> → 경로 입력 → **굽고 저장**.
결과가 `gunbaked.js` 로 바로 기록되고, 페이지 아래 미리보기에서 회전시켜 확인할 수 있습니다.

**4. 크기·위치를 맞춘다** — 게임을 새로고침하고 우상단 **DEBUG** → **총 메시(.glb)** 섹션에서
크기 · 좌우 · 높이 · 앞뒤 · 윤곽선 두께를 슬라이더로 맞춥니다. 마음에 드는 값이 나오면
`gunmesh.js` 맨 위 `scale` · `ox` · `oy` · `oz` 기본값에 적어 넣으세요(패널 값은 저장되지 않습니다).

**5. `gunbaked.js` 를 커밋한다.** `Mesh/*.glb` 커밋은 선택입니다 — 없어도 게임은 돌고,
다시 구울 때만 필요합니다.

### 축 — 제일 자주 틀리는 곳

glTF 는 **오른손**(+X 오른쪽 · +Y 위 · +Z 뒤), 이 게임은 **왼손**(+Z 앞)입니다.
지금 모델은 총구가 −X, 위가 +Y 라서 `local = (-z, y, -x)` 로 옮깁니다.

> 오른손 → 왼손 변환은 **행렬식이 −1** 이어야 합니다. 축을 짝수 번 바꾸면(행렬식 +1)
> 모델이 **거울상**이 됩니다. 대칭인 총은 티가 잘 안 나지만 텍스처의 글자가 뒤집힙니다.

### 감기 방향(winding)

이 게임의 메시(캡슐·구·박스)는 **바깥면이 CW** 규약이고, 툰 윤곽선이 그걸 전제로
`BACK` 을 컬링합니다. glTF 는 바깥면이 CCW 라서 `build()` 에서 인덱스를 뒤집습니다.

> **총이 통째로 새까맣게 나오면** 십중팔구 이것입니다. 윤곽선 껍질에서 가까운 면이
> 살아남아 본체를 덮은 것이지, 색이 안 구워진 게 아닙니다.
> 확인: 콘솔에서 `GunMesh.outlineW = 0` — 색이 제대로 보이면 감기 문제가 맞습니다.

### 지원 범위

- 삼각형 프리미티브 **1개**만 씁니다(`meshes[0]` 의 첫 삼각형 프리미티브).
- 정점 **65,535개 이하** — 인덱스가 uint16 입니다. 넘으면 로드가 거부되고 박스 총으로 떨어집니다.
- **스킨·애니메이션은 무시**합니다. 노드 변환(행렬 또는 TRS)은 하나만 적용합니다.
- 텍스처는 **베이스컬러만** 씁니다. 노멀맵·러프니스는 안 읽습니다(정점색 파이프라인이라 쓸 데가 없음).
- 텍스처는 긴 변 1024 로 줄여서 정점마다 UV 로 한 번 샘플링합니다.

### 왜 이렇게 만들었나

- **텍스처를 정점색에 굽는다** — 셰이더를 늘리지 않고 캐릭터(캡슐)와 같은 정점색 파이프라인에
  그대로 얹힙니다. 툰 윤곽선(법선으로 부풀린 껍질)도 같은 방식으로 붙습니다.
- **정적 VBO + 모델행렬** — 1만 삼각형을 매 프레임 CPU 로 옮길 수는 없습니다. 한 번만 올리고
  `VP×M` 만 바꿔 그립니다.
- **굽기를 브라우저가 한다** — Node 에는 JPEG 디코더가 없습니다. 새 의존성을 넣는 대신
  브라우저 디코더를 쓰고, 서버는 결과를 `/__bake` 로 받아 파일로 쓰기만 합니다(localhost 전용).
- **`gunbaked.js` 는 `<script src>`** — `levels/_all.js` 와 같은 이유입니다. `fetch` 가 필요 없어야
  `index.html` 을 더블클릭한 오프라인 플레이에서도 총 메시가 나옵니다.

### 안 될 때

| 증상 | 원인 |
|---|---|
| 총이 새까맣다 | 감기 방향 — 위 항목 참고 |
| 좌우가 뒤집혔다 | 축 변환의 행렬식이 +1 |
| 박스 총이 나온다 | 콘솔의 `[gunmesh]` 줄을 보세요. `file://` 인데 `gunbaked.js` 가 없으면 **정상 폴백**입니다 |
| 총구 섬광이 엉뚱한 곳 | `GunMesh.muzzle` 은 **z 최대쪽 2% 정점의 평균**입니다. 총열이 +z 가 아니면 축 변환이 틀린 것 |
| 모델을 바꿨는데 그대로 | 다시 굽지 않았습니다 (`tools/bake.html`). 게임은 `gunbaked.js` 만 봅니다 |
| 굽기 저장이 403 | 서버를 돌리는 PC 에서만 저장됩니다(`/__save` 와 같은 이유) |

메시를 아예 끄고 원래 박스 총으로 보려면 디버그 패널의 **메시 쓰기** 를 0 으로 두면 됩니다.
