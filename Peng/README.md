# PENG! — 공기폭발 협동 질주 (프로토타입)

WebGL 3D FPS(외부 라이브러리 없음). PoofGun(공기폭발 총)으로 발밑을 쏴 **로켓점프**로 협곡을 넘어 결승선까지. 솔로 또는 여러 명 협동.

## 혼자 플레이 (오프라인)

`index.html`을 브라우저로 그냥 열면 됩니다. 외부 라이브러리·인터넷 불필요. 멀티는 자동으로 비활성(솔로)로 폴백됩니다.

## 멀티플레이 (세션 코드로 함께)

의존성 0 Node 서버가 포함되어 있습니다. `npm install` 필요 없음.

```bash
node server.js
```

접속: <http://localhost:8090/>

> ⚠️ **반드시 위 주소로 여세요.** `index.html` 파일을 더블클릭해서 열거나(`file://`),
> 다른 정적 서버(예: `python -m http.server`) 주소로 열면 그쪽에는 멀티 서버가 없어
> "멀티 서버에 연결할 수 없습니다"가 뜹니다. 메인 메뉴 하단에 현재 상태
> (🟢 준비됨 / ⚠️ 안내)가 표시되니 확인하고 시작하세요.

### 함께 하는 순서

1. **호스트**: 메인 메뉴에서 **방 만들기** → 6자리 **세션 코드**가 나오고 대기방으로 이동
2. 그 코드를 친구에게 알려줍니다 (대기방의 *코드 복사* 사용)
3. **친구**: 같은 주소로 접속 → **방 참가하기** → 코드 입력 → 대기방 합류
4. 대기방에 2명 이상이 되면 호스트의 **게임 시작** 버튼이 활성화 → 누르면 **전원 동시 시작**

- 포트 변경: `PORT=3000 node server.js`
- 친구가 **다른 PC**에서 들어오려면 같은 공유기라면 호스트 PC의 내부 IP로 접속(`http://192.168.x.x:8090/`),
  인터넷 너머라면 8090 포트 개방 또는 터널(ngrok 등)이 필요합니다.
- 없는 코드를 입력하면 "방을 찾을 수 없어요"로 거부됩니다(빈 방이 생기지 않음).

### 동작 방식 (릴레이 넷코드)

각 클라이언트가 자기 물리를 로컬에서 돌리고, 자기 상태(위치·시점·반동)와 발사한 **폭발(blast)** 만 서버로 보냅니다. 서버는 같은 방의 다른 사람에게 그대로 중계합니다.

- 상대는 **청록 캡슐 + 총**으로 렌더됩니다.
- **핵심 협동**: 팀원이 쏜 펑건 폭발 반경 안에 있으면 **날아갑니다** — 서로 밀어서 협곡을 넘겨주세요!

## 캐릭터 편집기

메인 메뉴의 **캐릭터 편집기 열기** 또는 <http://localhost:8090/editor.html>

부품(박스·원통·반구·구)을 자유롭게 추가/이동/회전/크기조절해서 캐릭터를 만듭니다.

- **부품을 클릭**하면 선택되고, 나타나는 **색 축(빨강 X · 초록 Y · 파랑 Z)을 드래그**해
  3D 뷰에서 바로 옮길 수 있습니다. 빈 곳을 드래그하면 시점이 돌아갑니다.
- 속성 패널에서 **X/Y/Z 축 회전**(도 단위)도 조절합니다.

- 각 부품을 **몸통 / 머리 / 양팔 / 양다리** 중 어디에 붙일지 고를 수 있고,
  팔다리에 붙인 부품은 걸을 때 함께 흔들립니다.
- **관절·걷기** 탭에서 어깨·엉덩이 위치와 스윙 폭을 조절합니다.
- **저장**하면 같은 브라우저의 게임에 바로 적용되고, 멀티에서는 팀원 화면에도
  내 캐릭터가 그대로 보입니다.
- 다른 PC로 옮기려면 **저장** 탭의 JSON을 복사하거나 파일로 내보내세요.

캐릭터 정의는 `character.js` 에 있어 게임과 편집기가 같은 코드를 공유합니다.

## 게임 모드

대기방에서 호스트가 고른다(게스트 쪽은 잠긴다).

| 모드 | 규칙 |
|---|---|
| **협동** | 기존대로 함께 결승선까지. 혼자 못 넘는 협곡은 팀원이 밀어줘야 한다. |
| **경쟁** | 아레나에서 상대를 **밖으로 떨어뜨리면 1점**. 먼저 5점이면 승리. |

경쟁에서는 **플레이어끼리 몸이 부딪힌다**(서로 통과하지 못한다). 협동에서는 통과한다 —
좁은 발판 위에서 서로를 실수로 떨어뜨리게 되기 때문이다.

> 릴레이 넷코드라 상대를 직접 밀 수 없다(상대 위치는 그쪽 클라이언트가 정한다).
> 그래서 **양쪽이 각자 자기만 겹친 양의 절반씩** 물러난다. 합치면 정확히 떨어지고
> 한쪽만 튕겨 나가는 비대칭도 안 생긴다. 밀리다 벽에 파고들지 않도록 파고드는 축은 되돌린다.
> 머리 위·발밑처럼 세로로 안 겹치면 통과시킨다(위에서 떨어질 때 끼는 것 방지).

경쟁을 고르면 아레나 맵이 자동으로 선택된다(협동 맵에는 떨어뜨릴 가장자리가 없다).
떨어진 사람이 직접 신고하고 받은 쪽도 같은 규칙을 적용하므로 양쪽 점수가 어긋나지 않는다.

대기방에서 **내 몸통 색**도 고를 수 있다. 고른 색은 저장되고 팀원 화면에도 그대로 보인다.

### 콘텐츠 브라우저

패널의 아이템을 **뷰포트로 끌어다 놓으면** 배치됩니다. 드롭 지점은 광선이 맞은 발판 윗면,
없으면 바닥 평면입니다. 끄는 동안 놓일 자리가 미리 보입니다.

| 코스 | 장식 |
|---|---|
| 발판 · 발판(주황) · 결승 발판 · 상자 | 나무 · 침엽수 · 바위 · 풀 · 기둥 · 먼 바닥 |

나무처럼 여러 박스로 된 프롭은 **하나로 묶여서** 선택·이동·삭제됩니다.

> **장식(`deco`)은 충돌하지 않습니다.** 나무·풀이 보이지 않는 벽이 되면 안 되기 때문입니다.
> 반대로 밟고 올라설 발판은 장식 체크를 꺼야 합니다.

### 구간 자동 배치

`+ 점프` / `+ 로켓` / `+ 협동` 버튼은 마지막(또는 선택한) 발판에서 **그 난이도가 되는 거리**에
새 발판과 체크포인트를 함께 놓습니다. 높이차를 입력하면 그만큼 감안해 거리를 줄입니다.
협동 전용 구간을 손으로 계산할 필요가 없습니다.

> **회전은 지원하지 않습니다.** 게임 충돌이 축 정렬 AABB(`aabbHit`)라서 박스를 돌리면
> 화면만 돌아가고 충돌은 그대로 남습니다 — 보이는 곳에 못 서고 안 보이는 벽에 부딪힙니다.
> 회전을 넣으려면 충돌을 OBB/SAT로 갈아엎어야 하고 기존 발판 감각이 전부 바뀝니다.

### 도달 가능성 분석 — 이 에디터의 핵심

에디터는 게임과 **같은 물리 상수**(`level.js` 의 `PENG.PHYS`)로 협곡마다 넘을 수 있는지 계산해
라벨을 붙입니다. 감으로 배치하고 매번 실행해 볼 필요가 없습니다.

| 라벨 | 뜻 | 평지 기준 한계 |
|---|---|---|
| **점프** | 그냥 점프로 넘어감 | 4.85m |
| **로켓점프** | 자기 발밑을 쏴야 넘어감 | 10.83m |
| **협동 전용** | **혼자서는 불가능** — 팀원이 밀어줘야 넘어감 | 15.72m |
| **불가능** | 아무도 못 넘음 → 클리어 불가 맵 | — |

높이차가 있으면 한계가 줄어듭니다(예: 3m 올라가야 하면 일반 점프는 아예 불가).
선택한 발판에서 다음 발판 쪽으로 **궤적 3개**(초록=점프 / 주황=로켓 / 하늘=협동)가 그려지므로,
옆에서 보면 어느 방식으로 닿는지 눈으로 확인할 수 있습니다.

패널 맨 아래 판정문이 *"혼자서도 전부 클리어 가능"* 이라고 나오면 2인 게임의 이유가 없는 맵입니다.
**협동 전용 구간을 최소 하나** 넣으세요.

### 저장하는 법

- **▶ 시험 플레이** — 저장 없이 바로 실제 게임으로 확인 (편집본이 그대로 실행됩니다)
- **💾 저장** — `levels/<이름>.js` 에 **바로 기록됩니다.** 게임을 새로고침하면 맵 목록에 뜹니다.
  파일을 옮기거나 HTML 을 고칠 필요가 없습니다.
- **⬇ 다운로드 / 📋 복사** — 서버 없이 쓸 때의 폴백

> 체크포인트를 빠뜨리면 리스폰이 시작점으로 날아갑니다. **체크포인트 자동 생성** 버튼을 쓰세요.

저장은 **서버를 돌리는 PC 에서만** 됩니다. 서버가 `0.0.0.0` 에 열려 있어(친구 LAN 접속용)
누구나 파일을 쓸 수 있으면 안 되기 때문에, `/__save` 는 localhost 요청만 받습니다.
서버가 없으면(`file://` 로 연 경우) 자동으로 다운로드로 떨어집니다.

### 레벨 파일 형식

`levels/*.js` 는 JSON 이 아니라 **고전 `<script>` 로 로드되는 .js** 입니다.
`index.html` 을 더블클릭해서 여는 오프라인 플레이(`file://`)에서 `fetch`/ES 모듈이
CORS 로 막히기 때문입니다. 이 형식을 바꾸면 오프라인 솔로 플레이가 깨집니다.

HTML 이 참조하는 건 **`levels/_all.js` 하나뿐**입니다. 이 파일은 `server.js` 가
`levels/` 폴더를 훑어 자동으로 만들고, 파일이 추가·수정·삭제되면 즉시 다시 만듭니다.
**맵을 추가해도 HTML 을 고칠 일이 없습니다.**

> `_all.js` 는 생성물이지만 **커밋해야 합니다.** 서버를 켜지 않고 `index.html` 을
> 더블클릭해서 여는 사람에게는 이 파일이 이미 있어야 맵이 뜹니다.

```js
PENG.defineLevel('내맵', {
  name: '표시 이름',
  boxes: [ {cx:0, cy:-0.5, cz:0, hx:3, hy:0.5, hz:3, col:'#5a7bb0'} ],  // deco:true = 분석 제외
  goal: {cx:0, cy:0.5, cz:30, r:3.2},
  checkpoints: [ {x:0, y:0, z:0} ],
  killY: -14, start: {x:0, y:0, z:-2},
  hints: [ '체크포인트 0 에서 뜨는 안내' ]
});
```

멀티에서는 **호스트가 고른 맵**으로 전원이 함께 시작합니다(게스트의 맵 선택은 잠깁니다).
상대에게 없는 맵이면 기본 맵으로 떨어집니다.

## 3D 메시 넣기 (.glb)

총은 원래 박스 5개(`index.html` 의 `GUN`)였고 지금은 `Mesh/ShockWave_Gun.glb` 로 그립니다.
렌더러에 **외부 라이브러리가 없으므로**(three.js 없음) `gunmesh.js` 가 .glb 를 직접 읽습니다.

| 파일 | 역할 |
|---|---|
| `Mesh/*.glb` | 원본 모델. **소스일 뿐** — 게임은 평소에 안 읽습니다 |
| `gunbaked.js` | 구워진 정점(위치·색·법선·인덱스) 190KB. **게임이 실제로 쓰는 것** |
| `gunmesh.js` | .glb 파서 + 굽기 + 그리기. 배치값(크기·위치)의 기본값도 여기 맨 위 |
| `tools/bake.html` | 굽는 도구 (브라우저) |
| `tools/inspect_glb.js` | 모델 훑어보기 (터미널) |

### 새 모델로 바꾸는 순서

**1. 축이 어느 쪽인지 본다** — 터미널에서는 모델을 못 보므로 실루엣을 뽑습니다.

```bash
node tools/inspect_glb.js Mesh/새모델.glb
```

정점 수·바운딩박스·축별 단면표를 찍고, 같은 폴더에 `view_XY.png` · `view_XZ.png` ·
`view_ZY.png`(와이어프레임 실루엣, **빨간 십자 = 원점**)와 `basecolor.jpg` 를 남깁니다.
그림을 보면 총구가 어느 축의 +/− 인지 바로 판단됩니다.

**2. `gunmesh.js` 의 축 변환을 모델에 맞춘다** — `build()` 안의 이 줄입니다.

```js
var lx = -q[2], ly = q[1], lz = -q[0];   // local = (-z, y, -x)
```

**3. 굽는다** — 서버를 켜고 <http://localhost:8090/tools/bake.html> → 경로 입력 → **굽고 저장**.
결과가 `gunbaked.js` 로 바로 기록되고, 페이지 아래 미리보기에서 회전시켜 확인할 수 있습니다.

**4. 크기·위치를 맞춘다** — 게임을 새로고침하고 우상단 **DEBUG** → **총 메시(.glb)** 섹션에서
크기 · 좌우 · 높이 · 앞뒤 · 윤곽선 두께를 슬라이더로 맞춥니다. 마음에 드는 값이 나오면
`gunmesh.js` 맨 위 `scale` · `ox` · `oy` · `oz` 기본값에 적어 넣으세요(패널 값은 저장되지 않습니다).

**5. `gunbaked.js` 를 커밋한다.** `Mesh/*.glb` 커밋은 선택입니다 — 없어도 게임은 돌고,
다시 구울 때만 필요합니다.

### 축 — 제일 자주 틀리는 곳

glTF 는 **오른손**(+X 오른쪽 · +Y 위 · +Z 뒤), 이 게임은 **왼손**(+Z 앞)입니다.
지금 모델은 총구가 −X, 위가 +Y 라서 `local = (-z, y, -x)` 로 옮깁니다.

> 오른손 → 왼손 변환은 **행렬식이 −1** 이어야 합니다. 축을 짝수 번 바꾸면(행렬식 +1)
> 모델이 **거울상**이 됩니다. 대칭인 총은 티가 잘 안 나지만 텍스처의 글자가 뒤집힙니다.

### 감기 방향(winding)

이 게임의 메시(캡슐·구·박스)는 **바깥면이 CW** 규약이고, 툰 윤곽선이 그걸 전제로
`BACK` 을 컬링합니다. glTF 는 바깥면이 CCW 라서 `build()` 에서 인덱스를 뒤집습니다.

> **총이 통째로 새까맣게 나오면** 십중팔구 이것입니다. 윤곽선 껍질에서 가까운 면이
> 살아남아 본체를 덮은 것이지, 색이 안 구워진 게 아닙니다.
> 확인: 콘솔에서 `GunMesh.outlineW = 0` — 색이 제대로 보이면 감기 문제가 맞습니다.

### 지원 범위

- 삼각형 프리미티브 **1개**만 씁니다(`meshes[0]` 의 첫 삼각형 프리미티브).
- 정점 **65,535개 이하** — 인덱스가 uint16 입니다. 넘으면 로드가 거부되고 박스 총으로 떨어집니다.
- **스킨·애니메이션은 무시**합니다. 노드 변환(행렬 또는 TRS)은 하나만 적용합니다.
- 텍스처는 **베이스컬러만** 씁니다. 노멀맵·러프니스는 안 읽습니다(정점색 파이프라인이라 쓸 데가 없음).
- 텍스처는 긴 변 1024 로 줄여서 정점마다 UV 로 한 번 샘플링합니다.

### 왜 이렇게 만들었나

- **텍스처를 정점색에 굽는다** — 셰이더를 늘리지 않고 캐릭터(캡슐)와 같은 정점색 파이프라인에
  그대로 얹힙니다. 툰 윤곽선(법선으로 부풀린 껍질)도 같은 방식으로 붙습니다.
- **정적 VBO + 모델행렬** — 1만 삼각형을 매 프레임 CPU 로 옮길 수는 없습니다. 한 번만 올리고
  `VP×M` 만 바꿔 그립니다.
- **굽기를 브라우저가 한다** — Node 에는 JPEG 디코더가 없습니다. 새 의존성을 넣는 대신
  브라우저 디코더를 쓰고, 서버는 결과를 `/__bake` 로 받아 파일로 쓰기만 합니다(localhost 전용).
- **`gunbaked.js` 는 `<script src>`** — `levels/_all.js` 와 같은 이유입니다. `fetch` 가 필요 없어야
  `index.html` 을 더블클릭한 오프라인 플레이에서도 총 메시가 나옵니다.

### 안 될 때

| 증상 | 원인 |
|---|---|
| 총이 새까맣다 | 감기 방향 — 위 항목 참고 |
| 좌우가 뒤집혔다 | 축 변환의 행렬식이 +1 |
| 박스 총이 나온다 | 콘솔의 `[gunmesh]` 줄을 보세요. `file://` 인데 `gunbaked.js` 가 없으면 **정상 폴백**입니다 |
| 총구 섬광이 엉뚱한 곳 | `GunMesh.muzzle` 은 **z 최대쪽 2% 정점의 평균**입니다. 총열이 +z 가 아니면 축 변환이 틀린 것 |
| 모델을 바꿨는데 그대로 | 다시 굽지 않았습니다 (`tools/bake.html`). 게임은 `gunbaked.js` 만 봅니다 |
| 굽기 저장이 403 | 서버를 돌리는 PC 에서만 저장됩니다(`/__save` 와 같은 이유) |

메시를 아예 끄고 원래 박스 총으로 보려면 디버그 패널의 **메시 쓰기** 를 0 으로 두면 됩니다.
